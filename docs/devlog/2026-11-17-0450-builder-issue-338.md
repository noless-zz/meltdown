## Summary

- `MapHologram.set_markers(exit_position, reactor_position, reactor_known)`: an `Exit`
  marker (a cube) and a `Reactor` marker (a ball), placed with the same fit transform as the
  lines and the ship marker. Both stay hidden until `set_markers` is called; the reactor
  marker shows only while `reactor_known` is true. The level-space positions are kept, so
  `build()` re-fits them when more boxes are explored.
- The exit is a cube and the reactor a ball, as well as having different colours, so they can
  be told apart without relying on colour alone.
- New optional keys in `game/xr/map_look.json`: `exit_color`, `exit_radius_m` (half the
  cube's edge), `reactor_color`, `reactor_radius_m`. A file without them keeps the built-in
  values (green exit, magenta reactor, 1 cm). Unknown keys are still rejected.
- Look parsing moved to the new `game/xr/map_look.gd` (`MapLook`), as the issue suggested, so
  `map_hologram.gd` stays at 267 lines. `MapHologram.parse_look` and `FALLBACK_LOOK` still
  exist and forward to `MapLook`.
- Still unwired: `map_wiring.gd` and `main.gd` are unchanged.
