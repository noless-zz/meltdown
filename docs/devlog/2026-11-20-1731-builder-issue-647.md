## Summary

#647 builds on #646's notice and `update_wiring.gd`, which exist only on #668's branch. The
routine branches from `main`, so this run built the part that stands alone and opened #673
(`triage`) for the wiring once #668 merges (builder.md step 8).

- `meta/update_download.gd` (`UpdateDownload`): checksum file first, then the APK under the
  fixed name `meltdown_update.apk` in `OS.get_user_data_dir()` (the activity's files directory
  on Android), replacing an earlier one. Parses with `UpdateCheck.parse_sha256()`. A mismatch
  deletes the APK and says "Download damaged, try again"; a failure or cancel deletes partial
  files. An up-to-date result says "Up to date: <short>" and fetches nothing. Emits `changed`
  (progress text from the body size), `verified(path)` and `ended(status, text)`.
- `meta/chunked_sha256.gd`: hashes 256 KB at a time, four chunks per `step()`, so an 89 MB APK
  takes about a second of frames and never a second copy in memory.
- `meta/update_downloader.gd` interface and `meta/http_update_downloader.gd` (`HTTPRequest`
  writing to `download_file`, threaded, no body limit, 900 s timeout for the APK).
- Tests: `test_update_download.gd` (14) and `test_chunked_sha256.gd` (2), with
  `tests/fake_update_downloader.gd`.
