## Summary

- New `game/core/box_union.gd` (`BoxUnion`, `RefCounted`), built from an
  `Array[BoxBounds]`, kept in the order given.
- `box_for(point, radius)`: the lowest-index box that holds the sphere; otherwise the box
  whose interior shrunk by `radius` is nearest (squared distance, strictly less wins, so
  ties go to the lower index). On an axis where a box is narrower than the sphere, its
  shrunk interior is the centre line, the same rule `BoxBounds.contain_impact` uses.
  Returns null only for an empty union.
- `holds(point, radius)`: any box holds it.
- `contain_impact(ship)`: delegates to the box `box_for` picks; an empty union does
  nothing and returns `Vector3.ZERO`.
- `box_bounds.gd`, `sim.gd`, `robot_state.gd` and `salvage_item.gd` untouched; wiring the
  union into the simulation is lane-a's later issue.

## Open questions

- A ship already far outside every box (spawned in rock) is pulled into the nearest box

  outside the union.
- An opening narrower than the ship's diameter is solid, because the sphere fits in
  neither box while crossing; level data should keep openings at least `2 * radius` wide
  for the largest ship or robot.
