## Summary

This run does three of the six criteria. The other two are split out because they would
collide with open lane-c pull requests:

- **Left-handed aim (criterion 3).** New `xr/aim_hand.gd` (`AimHand`). It is the one place
  that says which controller aims: the right one, or the left one when the rig's `mapping`
  is left-handed. `HubWiring._point`, `ShaftChoiceWiring._point` and `XRRig.point_ray` all
  read the pose from it, so the highlight, the ray and the hand it hangs from always agree.
  Right-handed mode is unchanged.
- **Scripted aim pose (criterion 4).** `AimHand.script_pose(rig, hand, pose)` stores a pose
  per hand as metadata on the rig. It is read only while no XR interface is initialised, so
  a headset session never sees it. `clear_scripted` drops it.
- **Inside a station (criterion 1).** `AimTargets.station_hit` no longer returns null while
  a station is in use. The new `AimTargets.slot_hit` uses the same steps as
  `HubStations._point_in_station` (the drawing's `point_on`, then the hub text's `slot_at`)
  and ends the ray on the ray point nearest the picked slot (Fitting Bay) or tree node
  (Workbench, Parts Locker). When nothing is picked, the ray fades out at its length. Board
  stations draw nothing to point at, so the ray fades there as before.
- **Not done:** criterion 2, ending on the dev menu row (#1519, after #1515), and
  criterion 5, `suites/m6/hands.json` (#1520, after #1501 and #1515 because both edit the m6
  suite files). #1515 already shows the ray, fading, while the menu is open.

Compatibility with #1515: its branch was merged locally on top of this one. The merge has no
conflicts, and the aim tests (59) and base label tests (8) pass on the merged code.
