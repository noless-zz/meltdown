# 2026-11-16 Builder, issue #147 (lane-c)

Scheduled Builder run in lane-c. No open pull request closed a lane-c issue (#175 is lane-a,
#176 lane-b), so there was nothing to fix. The lowest `ready` lane-c issue in M1 was #147,
the playtest report that control labels overlap each other and the distance markers (PLT-5,
CMF-4). Named in Israel time (UTC+2), like the entries before it.

## Summary

- `game/xr/control_label_set.gd` (`ControlLabelSet`, new): one hand's labels. Every label
  sits in a single column on the outer side of its hand, one row per control in the order
  the controls sit on the controller, with the text running outward, so the two hands'
  labels never share space. Each label has a thin leader line to its control's point.
- Text is now 32 px at 0.28 mm per pixel, about 9 mm (was 16 mm); rows are 17 mm apart
  and a line with its outline is about 14.8 mm. The reasoning is in the constants.
- `game/xr/label_fade.gd` + `label_fade.json` (`LabelFade`): labels fade out after 5 s with
  the hand more than 25 degrees off the view axis and fade back in (0.5 s) when it comes
  near. Range-checked data file.
- `controller_model.gd` delegates labels to `ControlLabelSet` and gains `CONTROL_POINTS`;
  `xr_rig.gd` runs one fade per hand from the camera each frame. `show_labels` still hides
  everything at once.

## Test results

Godot 4.7.2-stable, run locally exactly as CI does: 465 tests, 0 failed (449 on `main`).
Mutation checks: rows 10 mm apart fails the overlap tests (left grip over left trigger);
labels on the inner side fail the leader and outward-text tests.

## Open questions

- The fade counts from when the rig runs, not from the start of flight, because the rig
  does not know whether the ship is flying. In flat mode the hands sit at the floor, so the
  labels fade after 5 s there too.
- The neutral pose in the test puts the hands 15 cm below the eye; the issue gave no height.
- Leader lines are one pixel wide (`PRIMITIVE_LINES`); they may shimmer in the headset.
