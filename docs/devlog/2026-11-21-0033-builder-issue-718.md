## Summary

- New `game/acceptance/acceptance_screenshots.gd` (`AcceptanceScreenshots`): parses a step's
  `screenshot_at_ticks` (whole ticks, 0 up to the replay's length, read from the replay when it
  can be; negative, past-the-end, fractional, bool and repeated ticks rejected naming the entry)
  and `screenshot_at_end` (bool); both need a replay. While the replay flies it saves the main
  viewport's last drawn frame as `user://acceptance/<suite>/<step>_<tick>.png`, and lists each
  tick with its `path` and `view`, or `skipped` and the reason (headless display, no image from
  the renderer, write error, tick never reached). Skips never fail a step.
- `AcceptanceStep`: `screenshot_ticks`, `screenshot_at_end`. `AcceptanceSuite`: the two keys.
- `AcceptanceReport.add_step`: optional `screenshots`, written under the step only when it has any.
- `AcceptanceRunner`: a public `screenshots` field (tests pass their own image source); takes
  the screenshot for the session's tick before flying it, so the last drawn frame shows that
  tick. Kept at 299 lines by folding the class comment and `_device_name`.
- `m1` `flight_axes` and `m2` `ship_destroyed_in_test_tunnel` (its first step) get
  `screenshot_at_end`.
