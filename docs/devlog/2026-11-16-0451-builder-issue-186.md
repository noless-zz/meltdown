## Summary

- New `game/view/projectile_view.gd` (`ProjectileView`, `Node3D`):
  `show_projectiles(projectiles, alpha)` draws one pooled, unshaded, emissive cylinder
  bolt per projectile, never writing to them (MP-2). Bolts are placed with
  `position + velocity * TICK_DT * (alpha - 1)` and point along their velocity.
- Fired-this-tick rule: the view remembers the position each projectile had when first
  shown and draws it where it is until it moves. On the first call this is exactly the
  issue's "not shown on the previous call" rule; it also holds when several headset
  frames fall within one tick (90 Hz frames on a 60 Hz tick), where the literal rule
  would pull a just-fired bolt one tick behind the muzzle on the second frame.
- New `game/view/projectile_look.json`: `bolt_length_m`, `bolt_radius_m`,
  `emission_color` (`[r, g, b]`), range-checked; a missing or rejected file keeps the
  defaults, sets `look_error` and pushes a warning naming the field.
- Not wired into `main.gd`; that is lane-b's #189.
