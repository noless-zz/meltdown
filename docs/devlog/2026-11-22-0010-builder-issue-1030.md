## Summary

- New `core/ship_part_def.gd` (`ShipPartDef`): `id`, `name`, `kind` and `stats`, a map of
  `ShipTuning` keys to multipliers. Each kind may only change its own keys (modules none
  yet), and each multiplier is 0.5 to 1.5. Unknown, missing and out-of-range keys, and an
  `id` that does not match the file name, are errors that start with the file name.
- `ShipPartDef.apply(tuning_data, parts)` returns a copy of the ship data with the parts
  applied in id order, then holds every number inside `ShipTuning.RANGES` (a key's bound
  that names another key is read after that key is final). No parts returns an exact copy.
- New `data/ship_parts/`: 3 shields, 2 hulls, 2 engines and the 3 utility modules the
  upgrade tree already grants, with empty stats (10 part files).
  `ribbed_frame` is the second hull; no upgrade grants it yet. Every non-weapon `grants` id
  now has a part file of its kind; no upgrade file changed.
