## Summary

- New `game/xr/break_choice.gd` (`BreakChoice`): saves `{"enabled": bool}` in
  `user://meltdown_break.json`, the way `PanelCorner` and `ControlsChoice` save theirs.
  A bad file is ignored with a warning naming it, and the data file's `enabled` is used
  instead.
- `--break-reminder=on|off` or the intent extra `meltdown_break_reminder` sets the
  reminder for this start and saves it (`for_launch`). The argument wins over the extra,
  and a bad value is ignored with a warning naming it. The order is: switch, then saved
  choice, then the data file's `enabled`.
- `BreakPromptWiring` holds a `choice`, applies it in `attach` (in place of
  `BreakPrompt.apply_setting`), and exposes `set_enabled(bool)`. That switches the
  reminder, saves the choice and hides a showing prompt in the same call. Turned back
  on, it waits a whole interval, as `BreakReminder.set_enabled` already did.
- `off_text` in `break_prompt.json` (and the parser's fallback) is now "Reminders can be
  switched off in the menu."
- `main.gd`, the dev menu files and `core/` are untouched.
