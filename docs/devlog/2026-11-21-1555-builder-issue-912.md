# Builder 2026-11-21 15:55, issue #912 (lane-a)

**Issue:** #912, Playtest: the reactor is usually next to the exit; place it far from the entrance
(GEN-1, GEN-3, RUN-3, RUN-5, ARC-2, ARC-4, DEV-7).

## Summary

- Cause confirmed: `GeneratedLevel._place_reactor` counted joins from module 0, but the ship starts
  and escapes at the oldest open connector, which can be on any module.
- New `game/gen/reactor_far.gd` (`ReactorFar`): reads a level's modules from the new
  `LevelDef.box_modules` (doorway and bridge boxes are -1), joins modules through doorway and bridge
  boxes, counts joins from the start's module, and measures every far module's escape path with
  `EscapePath`. The generator takes the longest path, ties to the lowest placement.
- `EscapePath.lengths_mm`: one search from the start for every candidate. A unit test checks it equals
  `length_mm` for every box centre on 20 seeds.
- `reactor.json` gains `min_escape_fraction: 0.6`. `min_hops` now counts from the start's module and
  must be at least 2, so the reactor is never in the start's module or a module joined to it.
- New validator check `reactor_far` (in `LevelValidator.CHECKS`, timed under "escape"). The validator
  gets the fraction from `SeedLevel`, the same way the debris plan gets the validator.
- m3: only `bot_generated_sight` (seed 31, the owner's seed) moved. Seeds 43, 26 and 29 kept their
  reactors, so their replays and hashes are unchanged.
