## Summary

- New `net/run_level_rules.gd` (`RunLevelRules`): reads `data/components/` (every kind file
  and `pickup.json`) and `data/miners/rescue.json`, and installs `ComponentPickup` and
  `MinerRescue` with the level's `miners` on the sim and in the replay together. A rejected
  file logs one line naming the file and key and leaves that feature off.
- `LevelStart.session_for` (used by `main.use_level` and `fresh_session`) installs them only
  when the path is the level the run flies now and `RunWiring.level_rules` is on (default).
  `--level`, `--seed`, the tunnel and the dev menu's levels stay as they were.
- Replay format 18: optional `components {...}` and `rescue {...,"miners":[...]}` lines
  (`core/replay_rules_line.gd`); with `components`, robot lines carry the drop table so a
  replay drops what the live run dropped. `Replay.run` and `ReplayInputSource` install the
  rules. A replay without the lines is still written as version 17, so every replay text and
  every level hash taken from it stays byte-identical.
- Banking: no change. `RunWiring.after_session` already banks `sim.collected`; it is now
  non-empty on a run level.
- Acceptance: new `components_bank` check (`AcceptanceComponentsBankCheck`, field
  `expected_banked`) and m4 step. It reuses `run_advances.replay`: with drops on, the bot
  pilot's escape from level 1 of run 12345 flies through one cell salt; the restart press
  banks `{"cell_salts": 1}`. Only a step with this check turns the rules on
  (`AcceptanceRunStep.begin`), so run_advances and shaft_choice keep their pinned hashes.
