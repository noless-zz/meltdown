## Summary

- `game/acceptance/acceptance_suite.gd` (`AcceptanceSuite`): parses a suite JSON (`name`,
  ordered `steps`). Unknown keys, unknown or repeated checks, a missing or repeated `id`, a
  preset outside 1..4, a non-whole number and a bool where a number belongs are rejected
  with the field named (`steps[0].checks[1]: unknown check ...`). `final_hash` needs both
  `replay` and `expected_hash`; an `expected_hash` without the check is rejected too.
- `load_named("all")` returns every suite in `game/acceptance/suites/` in file-name order;
  another name loads that one file. Names are limited to `a-z0-9_-` so a launch argument
  cannot reach outside the folder, and a suite's `name` must match its file name.
- `game/acceptance/acceptance_step.gd` (`AcceptanceStep`): the parsed step; the known
  checks are constants there (`xr_session`, `final_hash`, `no_script_errors`).
- `game/acceptance/acceptance_report.gd` (`AcceptanceReport`): per-step `pass` / `fail` /
  `skipped` with message and measurements, plus build commit, device and suite. JSON keys
  are sorted at every level; `to_log_lines()` puts the tab-indented JSON, one log line per
  JSON line, between `MELTDOWN_ACCEPTANCE_BEGIN` and `MELTDOWN_ACCEPTANCE_END`. `passed()`
  is false with a failed step, or when no step passed or failed (all skipped).
- `m0.json` (one `xr_session` step) and `m1.json` (flies `basic_flight.replay`, copied to
  `game/acceptance/replays/`, to hash 861662111).
- Layer rules: the scanner only covers `core/`, `gen/` and `net/`; `main.gd` has no rule,
  so the new folder needs none either. `test_layer_rules.gd` is unchanged.
