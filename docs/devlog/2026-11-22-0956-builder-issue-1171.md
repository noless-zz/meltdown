## Summary

- New `game/start_choice.gd` (`StartChoice`): `choose(args, extras, flight_test_done)`
  returns `hub` or `flight`. Any `--run`, `--level`, `--seed` or `--acceptance` argument,
  any non-blank `meltdown_level`, `meltdown_seed`, `meltdown_run` or `meltdown_acceptance`
  extra, or a first launch (flight test not done) flies at once, as before. A switch
  with a bad value also still flies, so a typo is not hidden by the hub.
- A hub start makes `run:<random seed>` the source, as a run after a loss picks its seed,
  so `LevelStart.choose` builds the run with its profile, fitting and save stores.
  `StartChoice.open_hub` then opens `HubWiring` on that run and leaves the end screen
  as a restart press leaves it: the view is dark, the ship is held (`ShipHold` sees the
  fade), and the launch or resume fades the view in exactly as between runs (CMF-8).
- `main.gd`: two lines for the choice, and the session no longer ticks while the hub is
  open, so the run's live first level cannot fight a held ship behind the start-up hub.
  Between runs the session behind the hub has already ended, so nothing changes there.
  Two doc comments joined to stay at 300 lines.
- A scene outside the tree (every unit test calling `_ready` by hand) never opens the
  hub, so tests do not depend on the machine's saved comfort choice.
