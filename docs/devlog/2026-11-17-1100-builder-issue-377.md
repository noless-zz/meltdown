## Summary

- New `game/tests/bot_escape_sweep.gd` (extends `SceneTree`, static functions so the test
  can call them): for each seed it builds the level as `seed_sweep.gd` does (10 modules,
  `reactor.json`), flies it with `BotPilot` through `LocalSession.for_level` until the
  outcome is not `RUNNING`, the ship is destroyed, or 36,000 ticks (ten minutes), prints one
  line per seed that did not escape (`seed S: OUTCOME at tick T: reason`), a details line,
  and `MELTDOWN_BOT_ESCAPE {"seeds":N,"cleared":C,"escaped":E,"rate":r}`. Cleared means the
  reactor was destroyed; the rate is escaped over cleared, to four places. Seeds with no
  reactor (or a level that did not build) are counted apart and never as cleared. Exit 0
  only when the rate is at least 0.95.
- New `game/tests/test_bot_escape_sweep.gd` (5 tests): 20 seeds at rate ≥ 0.95 within
  60 s; the summary's exact shape and that its JSON parses; seeds 1 to 3 swept twice give
  the same summary and failures, and each flight ends on the same tick, outcome and state
  hash; a 1-second countdown counts as cleared, `LOST`, not escaped, with a seed line; a
  level built without a reactor plan is `NO_REACTOR`.
- Nothing in `gen/`, `tools/` or the simulation changed.

## Open questions

- The issue builds levels with the reactor plan only, so the generated levels are flown
  without robots (`robots.json`, #378). With robots, "cleared" would also need the fight
  won; that is the rate G3's headset check will see. A follow-up could add a `--robots`
  option once robots on generated levels have a wake range (#391 devlog).
- 1,000 seeds take about 8 minutes, too long for every pull request; a nightly job could
  run it like `validate_seeds.gd` (needs a `.github/` change, so the owner's approval).
