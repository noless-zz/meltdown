## Issue

#1012: fitting crafted upgrades: the starting loadout from the ship file plus the
pilot's fitted upgrades (CRF-4, CMB-1, CRF-5, CMB-8, ARC-2, ARC-4).

## Summary

- New `game/meta/fitting.gd` (`Fitting`): an upgrade id per primary, secondary and
  utility slot.
  - `check(fitting, tree, crafted, ship_data)` gives `""` or one reason naming the slot:
    unknown upgrade, not crafted, same upgrade in two slots, a utility slot the ship
    does not have, wrong kind for the slot, or not fittable yet.
  - `loadout(fitting, tree, ship_data)` returns the ship file's `loadout` section with
    fitted slots replaced by the upgrade's `grants`; an empty fitting returns the section
    unchanged. The ship data is never modified.
  - `to_json()` / `parse_json()`; unknown or missing keys and bad slot lists are errors
    naming the key.
- Choices the issue left open, documented in the class comment:
  - "Right kind" of weapon slot: every weapon upgrade fits a primary slot; secondary
    slots refuse all upgrades, because the simulation has no secondary weapons yet
    (decision record 0004) and weapon files carry no slot kind.
  - Modules fit utility slots only once core knows the module
    (`ShipLoadout.UTILITY_MODULE_KINDS`, empty today). Otherwise the loadout would pass
    `check` and then be rejected by `ShipLoadout.from_data`. So no shipped module is
    fittable yet; the refusal says "not fittable yet".
  - Shield, hull and engine upgrades are refused as "not fittable yet", as the issue asks.
- No core file changed.
