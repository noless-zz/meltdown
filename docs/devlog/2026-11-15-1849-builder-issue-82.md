# 2026-11-15 Builder, issue #82 (lane-c)

Scheduled Builder run in lane-c. No open pull request closed a lane-c issue (#113 is lane-a,
#118 lane-b, #117 the Planner's), so there was nothing to fix. The run took the
lowest-numbered `ready` lane-c issue in M1: #82, a second control layout that puts both
directions of lift and of roll on one hand each, with layouts as data files (PLT-5, ARC-4,
FLT-1). The file is named in Israel time (UTC+2), like the entries before it.

## Summary

- `game/xr/layouts/thumbsticks_default.json`: today's `default_layout()`, unchanged.
- `game/xr/layouts/thumbsticks_paired.json`: right trigger up, right grip down; left trigger
  roll left, left grip roll right; sticks and afterburner as in the default.
- `ThumbstickMapping.from_json` and `from_file`: parse and validate a layout. Unknown axis,
  action or control names, non-number weights and weights outside -1..1 are rejected with
  the name in `error`; the mapping then keeps the built-in default. A missing file is
  rejected the same way. Path constants `DEFAULT_LAYOUT_FILE` and `PAIRED_LAYOUT_FILE`.
- `default_layout()` is unchanged, so nothing that uses it changes. Left-handed mode needs
  no new code: `_swap_hands` already works on any layout.
- `game/tests/test_thumbstick_layout_files.gd`: 10 tests.

## Open questions

- Nothing loads a layout file at runtime yet; choosing a layout is out of scope (lane-b,
  `main.gd` or settings). When something does, the export presets need `*.json` in
  `include_filter`: `all_resources` exports only resources, so plain JSON files may be left
  out of the Quest build. The same applies to `data/ships/default_ship.json`.
- `ControlLabels` labels any layout, so the paired layout's labels should read "down / up"
  on the right hand and "roll left / right" on the left; worth a look in the headset once
  the layout can be chosen.
- A layout file may leave an axis unbound; the issue did not ask for every axis to be
  required.
