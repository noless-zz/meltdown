## Issue

#1092: runs record the profile statistics: starts, escapes, wins, losses, miners,
components (CRW-2, RUN-7, CRF-2, SLV-3, ARC-2, DEV-6).

## Summary

- New `RunStatsRecorder` (`game/run_stats_recorder.gd`), held by `RunWiring.stats`. It
  calls `ProfileStats.record_run_start`, `record_escape`, `record_loss` and `record_win`
  and saves through the run's store. A refused call or a failed save is logged once per
  launch with `[meltdown run]` and kept in `stats.error`; the run never stops for it.
- `RunWiring`: `start` records the start and saves; `_bank` records the escape (level
  index, the miners that actually joined the crew, the components actually banked) and
  now always saves once per escape, with bank, crew and statistics together; a loss and
  a win each record and save. `escape_for_choice` goes through `_bank`, so an escape
  into a shaft choice is counted once.
- Single levels (`--level`, `--seed`, the dev menu) build no `RunWiring`, so they record
  nothing; leaving a run with the dev menu records nothing either.
- Acceptance: the m4 `run_advances` check now also judges the run's profile after the
  press: 1 run started, 1 level escaped, deepest level 1, no loss and no win (measured as
  `stats`). No suite field or hash changes. I extended the check instead of adding a
  step so that this pull request does not edit the same parser lines as #1114.
