## Issue

#1071: hub panel in the headset, the hub's lines drawn and driven with the stick and A
(CRW-2, CRF-3, CRF-4, ARC-3, ARC-4, MP-2, NAM-3).

## Summary

- `game/xr/hub_panel.gd` (`HubPanel`, `Node3D`): one `Label3D` per `lines()` entry, the
  title in its colour, the selected row marked with `mark_text` and coloured, a refused
  press's reason under the page until the next input. Hung and drawn like `ShaftPanel`.
- `update(held)` takes the dev menu's named actions (`menu_up/down/left/right/confirm`):
  each counts once on the frame it is pressed, the first one pressed wins the frame. A
  returns `{"pressed": selected(), "reason": press()}`; everything else returns `{}`.
  The dev menu has no stick auto-repeat, so neither does the panel: one row per flick.
- A button already held when `open` is called only counts after it is let go, so the
  press that opens the panel cannot craft at the same time.
- `game/xr/hub_panel.json` and `HubPanelLook`: mark text, four colours, title place, line
  step, three font sizes and pixel size, checked on load with errors naming the key.
- Layer rule: `CLAUDE.md` lets `xr/` depend only on `view/` and `core/`, but the issue
  hands the panel a `HubText` from `meta/`. The panel names no meta class: it takes any
  object with `HubText`'s six methods and calls them by name. The test feeds it a real
  `HubText`.
