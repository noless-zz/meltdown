# 2026-11-14 Manual session: issues #4 and #5

Built by hand in an interactive session at the owner's request, to get a testable APK
before the first Builder run. Both issues are in one pull request, which is an exception
to DEV-2.

## What changed

- OpenXR enabled, MSAA 4x and foveation set, ETC2/ASTC import enabled (Android needs it).
- `game/xr/xr_rig.tscn`: `XROrigin3D` with an `XRCamera3D` and two `XRController3D`.
- `game/view/test_tunnel.tscn`: 30 m tunnel built in code, three coloured lights, markers
  at 1, 5 and 20 m.
- `main.tscn` composes both and asks for 90 Hz once the session begins.
- `Android Quest` export preset, `tools/build.sh quest`, and a `Quest APK (debug)` CI job.

## Test results

- 9 unit tests pass headless. OpenXR fails to start in CI (no runtime) and the project
  falls back to flat rendering as intended.
- The CI job produced an 82 MB APK containing `libopenxr_loader.so` and a manifest with
  the Khronos immersive category and the head-tracking feature.

## Not verified

- Nothing has run on a headset yet. Whether the app opens immersive, tracks the head and
  holds frame rate is the owner's check for gate G0.

## Deviations from issue #5

- The Godot OpenXR Vendors plugin was not added. Since Godot 4.6 it is optional and the
  engine exports a working OpenXR APK without it. The manifest therefore has no
  Meta-specific entries. If the app opens as a flat panel on the Quest, or when Meta-only
  features are needed, add the plugin (follow-up issue filed).
- No project icon is set; the export logs a non-fatal error about it.
