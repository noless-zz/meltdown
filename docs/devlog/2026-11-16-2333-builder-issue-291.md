## Summary

- `LocalSession.for_level(level, ...)`: a session whose replay holds the level's boxes in
  order (the sim takes its walls back from the replay, rounded to millimetres, as the
  one-box constructor does), the ship at the level's start pose, and the level's robots
  resolved and armed through `SpawnLoader.resolve_list`, the code path `load_spawns` now
  uses too (#269).
- `game/level_switch.gd` (`LevelSwitch`), beside `main.gd` like `CombatWiring`: reads
  `--level=<name>` or the `meltdown_level` intent extra (the same way as `--acceptance`,
  #165), maps the name to `res://data/levels/<name>_level.json` (lower-case letters,
  digits and `_` only), loads and validates the level, and swaps the drawn `TestTunnel`
  for a `LevelView` of the level's union at the simulation's origin.
- `main.gd`: `use_level(path)` builds the level session and drawing; `_ready` calls it
  with the switch's path before anything is placed, so the rig starts at the level start.
  A missing or rejected file is printed and the tunnel stays. To keep `main.gd` under 300
  lines, the smoke-test report moved unchanged into `XrSmokeProbe.report`.
