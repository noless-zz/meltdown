## Summary

- `game/data/ships/default_ship.json` gains
  `"loadout": {"primary": ["pulse_cannon", ""], "secondary": ["", ""]}`.
- New `game/core/ship_loadout.gd` (`ShipLoadout`): reads the entry (optional; `""` is an
  empty slot), checks ids with the `RobotDef` rule, and `resolve(texts)` turns the
  caller's weapon file texts into `WeaponDef`s. Core opens no files: `weapon_ids()` tells
  the caller which `res://data/weapons/<id>.json` to read. A failed resolve arms nothing.
- `ShipTuning.parse_json` accepts the `loadout` key and reports its errors by field
  (`"loadout.primary" has 3 slots, at most 2`, `"loadout.primary[1]" is "Pulse", ...`).
  The tuning line of a replay still carries only the numbers.
- Replay format 7: one `weapon <kind> <slot> <id> <weapon json>` header line per filled
  slot. `Replay.run` calls the new `Sim.equip(loadout)`, which fills every ship's slots
  and is refused after the first tick. A replay without weapon lines is read and run
  exactly as before.
- Not wired into the session or main scene: `local_session.gd` and `main.gd` belong to
  lane-b's #189, which should read the weapon files, call `resolve`, `Sim.equip` and set
  `replay.loadout`.
