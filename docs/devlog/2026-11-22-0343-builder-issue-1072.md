## Issue

#1072: the mine scanner module shows trapped miners on the map (CRF-5, CRF-4, SLV-3,
MAP-1, ARC-1, ARC-4, MP-2).

## Summary

- `ShipLoadout.MINE_SCANNER_MODULE` ("mine_scanner") joins `UTILITY_MODULE_KINDS`, so a
  crafted scanner passes `Fitting.check` and a ship file may carry it.
- New `game/data/utility/mine_scanner.json` (`scan_radius_m`: 60) and
  `game/view/mine_scanner.gd` (`MineScanner`): reads the file and picks the trapped
  miners within the radius of the ship, walls ignored. The one-radius file check moved
  from `WideRadar` into `game/view/utility_radius.gd` (`UtilityRadius`), so both files are
  checked alike; `WideRadar`'s messages are unchanged.
- `MapWiring._scan` reads the ship copy's utility slots and a copy of the trapped miners
  (`MapRouteWiring.trapped_miners`, beside `reactor_destroyed`, since `map_wiring.gd` may
  not name the sim) each frame and hands the miners in range to the hologram, only when
  the set changed. No scanner, or no rescue in the run, marks nothing. A rescued miner
  leaves `trapped`, so its marker goes.
- `game/xr/map_miner_markers.gd` (`MapMinerMarkers`): one violet pin (a square pyramid on
  its point) per miner, one mesh for all. Colour and size are new optional keys
  `miner_color` and `miner_size_m` in `map_look.json` / `MapLook`. `MapHologram` gains
  `show_miners`; its class comment was tightened so it stays under the 300-line test.
- Tests that used `mine_scanner` as the example of an unknown module now use a made-up
  `deep_sonar`; the "not fittable yet" fitting test adds it to a copy of the tree.

## Tests

New `game/tests/test_mine_scanner.gd`, 9 tests: core accepts the module; a crafted one
fits; a miner 40 m away is marked with the scanner, not without it or with only the wide
radar; one 80 m away is not (one exactly 60 m away is); a rescued miner's marker goes;
the scan leaves the sim hash alone; the pin's look comes from `map_look.json` and a bad
size is named; the shipped data file loads; bad data names the file and the key.
`test_shipped_replays_keep_their_pinned_hashes` still passes. Full suite run locally with
Godot 4.7.2 headless, as CI does. The first full run caught two guard tests
(`map_wiring.gd` named `sim.`, `map_hologram.gd` passed 300 lines); both fixed.
