## Summary

- `LevelValidator` split as the issue asked: the `reactor` and `escape` checks moved unchanged
  into `game/gen/escape_checks.gd` (`EscapeChecks`), and the new check lives in
  `game/gen/robot_checks.gd` (`RobotChecks`). `level_validator.gd` is 214 lines.
- New `robots` check, last in `CHECKS`. Each robot must be held by a box with its radius plus a
  ship's diameter clear of the faces, worked in whole millimetres as `GeneratedLevel` places
  robots (single-precision box corners would otherwise fail a robot placed exactly its
  clearance from a face); one of those boxes must be reachable from the start; and it must not
  be inside any box of the start module. A level with no robots passes.
- `validate` gains two optional arguments: `robot_radii_mm` (radius by type id, for the
  generator's unresolved spawns; a resolved spawn uses its `RobotDef.radius`) and
  `start_module` (box indices). With no start module given, as for hand-built levels, the box
  holding the start stands for it. A robot with no known radius fails the check rather than
  being skipped.
- `RobotPlan.radii_by_id()` added for the validator's radii.
- `tests/seed_sweep.gd` loads `data/gen/robots.json` (and the robot files) and passes the plan
  to `to_level_def`; a broken `robots.json` fails every seed like the other data files. It
  passes the radii and the start placement's boxes to the validator, and its result counts
  `robots` placed. `by_check` picks up `robots` from `CHECKS`, so the summary line and the
  nightly 10,000-seed job count it with no further change.
- `generated_level.gd` and `mine_generator.gd` (lane-a) were not edited.
