## Summary

- `tools/device_acceptance.ps1`: a log poll or `pidof` that fails while the headset does not
  answer `adb shell true` is a drop, not a crash. It prints `the connection to the headset
  dropped at HH:MM:SS`, waits up to `-ReconnectSeconds` (300 s) for the same headset on any of
  its serials, prints `the headset is back at HH:MM:SS` and goes on. A headset that never
  returns fails the run with that reason. After a drop the end of `device.log` is filled from
  the headset's buffer. New `-Serial`, `-Unattended`, `-ReconnectSeconds`,
  `-ReconnectPollSeconds`.
- `tools/acceptance_headset.ps1`: `Select-Headset` (`-Serial`, else `ANDROID_SERIAL`, else
  Wi-Fi when the same `ro.serialno` is also on the cable), `Wait-Reconnect`, `Resume-AfterDrop`,
  `Save-Screenshot`.
- `tools/acceptance_recover.ps1` (new): clears `files/acceptance` with `run-as` before the start,
  copies every `.json` there into `from-headset/` at the end, merges suites the log lacked, reads
  `acceptance_exit.json` (`exit_code`, `exit`, else `failed`), and builds a partial suite from the
  step lines when there is neither exit line nor exit file.
- `tools/acceptance_common.ps1`: download and checksum moved here (`Get-CheckedApk`) to keep the
  main script near 300 lines (309).
- `game/acceptance/acceptance_controllers_check.gd`: with `meltdown_unattended=1` (or
  `--acceptance-unattended`), untracked controllers are **skipped** with the reason; tracked
  controllers with a missing binding still fail. The script sets the extra for scheduled
  workflow runs, `-Suite nightly` and `-Unattended`.
- `docs/device-acceptance.md`: choosing the headset, drops, recovered reports, unattended runs,
  and the 60 s USB reset: cause not found; Quest Link (Highwind) is the likeliest candidate, with
  three settings to try one at a time.
