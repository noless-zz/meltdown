## Issue

#1011: the chosen shaft's `robot_count` makes the next run level busier (RUN-1, GEN-2,
ARC-2, ARC-4, DEV-6).

## Summary

- `LevelSwitch` sources may carry a scale: `seed:<n>:robots=<scale>`. `seed_source`
  writes it only when the scale is not 1.0; `source_seed` and `source_robot_scale` read
  it (`seed:<n>` alone is 1.0; an empty, zero, negative or non-number scale is -1.0, and
  `load_level` refuses it). `load_level` passes the scale to `SeedLevel.load_level`.
- `RunWiring.level_robot_scale()` is `RunState.current_risk().robot_count` (1.0 for
  level 1, a run without shafts, or no run); `level_source()` uses it, so the scaled
  source names the level wherever the run identifies it, and `LevelStart.run_rules`
  still matches the run's level.
- `LevelStart.shown_level` and `DevMenuLevels.open` read the seed out of a scaled source,
  so the status panel and the dev menu still show the seed.
- `shaft_choice` (m4): the check expects the scaled source, and the pinned
  `expected_next_level_hash` is re-recorded (1431193924 -> 200686444) for run 12345's
  second offered shaft, `hot` (robots x1.1). The step test now also fails if the picked
  shaft does not scale the robots.
