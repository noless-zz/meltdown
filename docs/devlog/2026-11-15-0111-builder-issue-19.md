# 2026-11-15 Builder: issue #19, Quest APK and desktop client on main-latest

Scheduled Builder run. The owner asked for parallel Builder runs to finish M0 faster, so
this run skipped routine steps 2 and 3 and was assigned #19 directly. Other runs work on
#18 and #26 at the same time.

## Issue

#19 Publish the Quest APK and desktop client to the main-latest release (DEV-8, ARC-6,
PLT-4). The issue explicitly permits editing `.github/workflows/ci.yml`.

## Summary

- `.github/workflows/ci.yml`: one new job, `publish-clients`, placed after
  `publish-server`. It runs only on a push to `main`, needs `build`, `quest-apk` and
  `publish-server`, and is the only new job with `contents: write`. It downloads the
  `meltdown-quest-debug` and `meltdown-desktop-linux` artifacts, writes a `.sha256` for
  each, uploads each binary and then its checksum with `--clobber`, and retitles the
  release "Builds (main)" with notes naming all three targets and the commit.
- `publish-server` is unchanged, byte for byte. Because the client job is separate, a
  failed APK export skips only the client publish.
- Waiting for `publish-server` means only one job ever creates the release or moves its
  tag, so the two jobs cannot race.
- `docs/install-on-quest.md`: the direct `main-latest` link comes first; the artifact
  route stays for pull request builds; the uninstall note for a different debug key
  stays.

## Test results

- Godot is not installed in this environment; no game code changed.
- `actionlint` 1.x on `ci.yml`: no findings. The YAML parses and the job graph is as
  intended.
- CI on the pull request: see the pull request. The new job is skipped on pull requests by
  design, so it first runs on `main` after merge.

## Open questions

- On `main`, a new push cancels the running workflow (`cancel-in-progress`). If that
  happens between the server and client uploads, the release briefly holds builds from
  two commits. Each file still matches its own checksum.
- `publish-server` still writes its server-only notes on each push; `publish-clients`
  replaces them a few minutes later. If the APK fails, the server-only notes stay, which
  is accurate for the files of that commit but the older APK remains attached.
- The desktop binary downloaded from a release is not executable until `chmod +x`.
