## Summary

- `game/view/projectile_view.gd`: `set_viewer(at)` sets the camera position in the view's
  space; each `show_projectiles` then puts a pooled `OmniLight3D` on the `max_lights` shown
  bolts nearest it. Ties keep the order of the projectile list (only a strictly nearer
  bolt moves ahead), so the choice is deterministic for a given input.
- Lights are pooled like the bolts: the pool grows only when more bolts are lit than
  there are lights, never shrinks while the count holds, and a look file with a smaller
  budget frees the lights above it, so no more than `max_lights` light nodes ever exist.
  Lights cast no shadows and use the bolt's `emission_color`.
- `game/view/projectile_look.json`: `max_lights` (whole number, 0..8; 0 turns the lights
  off), `light_range` (0.5..30 m), `light_energy` (0..16). The cap of 8 is the mobile
  renderer's per-mesh omni light limit. Shipped values: 4 lights, 6 m, energy 1.5.
- New accessors `lit_bolts()`, `light_count()`, `light(index)` for tests and for wiring.
- Not wired into `main.gd`: nothing calls `set_viewer` yet; that belongs with the wiring
  of the view (lane-b's #189), which should pass the camera position each frame.
