## Summary

- **Icons (criterion 1).** The base's icon set (`data/hub/icons.json`) has a new `menu`
  group: 25 icons drawn the same way as the rest (flat rects, discs, rings, triangles),
  one per section row, Back and every entry. `dev_menu.json` names each row's icon in a
  new `icons` block (`xr/dev_menu_icons.gd` reads it). The menu's icons share one colour
  and always stand beside their label, so they are left out of the set's colour-distance
  rule (`HubIcons.SHAPE_ONLY_GROUPS`). The icon sheet now wraps a group longer than 8
  icons onto further rows, so the 25 menu icons do not shrink the other groups. Recorded
  in `docs/licences.md`.
- **Drawn values (criterion 2).** Each value helper says how it is drawn
  (`DevMenuValue.drawing()`): on/off entries as a switch, short lists (corner, comfort
  preset, controls, hands, pitch, foveation, level) as marks with the current one lit,
  render scale as a bar with its number beside it (`xr/dev_menu_value_drawing.gd`).
  Value words and notes show only on the highlighted row.
- **Readability (criterion 3).** The rows stand on a plate in the base screens' colour
  (`xr/dev_menu_look.gd`), so contrast can be held: words and lit marks at least 7:1, dim
  marks and icons at least 3:1, words at least 0.9° tall, icons no smaller. The Info lines
  are a little brighter (0.6, 0.66, 0.7) to reach 7:1 on it.
- **Presentation only (criterion 4).** `DevMenuModel` is untouched; a test drives the
  drawn menu and a bare model with the same presses and compares every result.
- **Files (criterion 5).** New drawing code is in four new `xr/` files; all under 300 lines.
- **Acceptance (criterion 6).** `menu_look` step in `suites/m6/menu.json`
  (`acceptance/checks/menu_look_check.gd`): the menu opens in the mine and at the base, the
  top list and the Comfort section are checked for an icon on every row and a drawing on
  every value row, and a screenshot of each is saved.
