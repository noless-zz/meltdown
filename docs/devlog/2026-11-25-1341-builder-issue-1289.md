## Summary

- `acceptance/render_budget.gd` (`RenderBudget`): limits read from
  `acceptance/checks/render_budget.json` (150 draw calls, 600,000 triangles both eyes,
  3584 MiB = 3.5 GB). Every key required, numeric and above 0; unknown keys rejected.
- `acceptance/render_stats.gd` (`RenderStats`): per-frame samples, nearest-rank 95th
  percentile, `judge` against a budget. Every metric's p95, max, sample count, budget and
  result go into the step's measurements, pass or fail. A metric with no samples is
  reported as skipped; none read at all makes the render part skipped, never passed.
- `read_frame` (view layer only): `RenderingServer.get_rendering_info` total draw calls and
  primitives, primitives times the XR view count (the mobile renderer's multiview pass
  counts each draw once), memory = `Performance.MEMORY_STATIC` + video memory. Headless,
  or static memory 0 (release build), reads as "not read".
- `AcceptanceFrameBudgetCheck` samples the render numbers on the same counted frames and
  its `judge` appends them to the summary; either the frame times or a render p95 over
  budget fails the step. Every step with `frame_budget` (m1 `frame_budget`, m6
  `stress_scene`, the soak) now reports them; no suite file changed.
