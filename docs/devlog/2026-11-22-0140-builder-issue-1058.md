## Issue

#1058: hub pages as text lines with a selected row and the action it takes (CRW-2,
CRF-3, CRF-4, ARC-4, MP-2, NAM-3).

## Summary

- New `meta/hub_text.gd` (`HubText`): `lines()` (title first), `selected_line()`,
  `move(delta)` clamped to the selectable rows, `turn_page(delta)` wrapping and resetting
  the row, `selected()` naming the action, and `press()` acting through `HubModel`
  (`craft`, `fit`, `launch_check`/`launch`) and returning its reason unchanged. A
  successful launch keeps the loadout section in `launched`. Section headers and empty-page
  texts are shown but skipped by the selection; crew, store and built rows can be selected
  and do nothing.
- Craft page: ready, locked and built sections; a locked row presses `craft` too, so the
  model's reason comes back. Fit page: per slot an information row, a "mount" row for each
  crafted upgrade of the slot's kind (weapon for primary, module for utility, none for
  secondary), a strip row when an upgrade is fitted; the launch row last.
- New `text` object in `data/hub/hub.json`: row patterns, slot names and crew stat names.
  Read by new `meta/hub_words.gd` (`HubWords`); `HubConfig` requires the key. Both are
  lane-c files; the issue listed only `hub_text.gd`, but `HubConfig` refuses unknown keys.
- Upgrade, component and role names come from their own data files; the ship file's
  stock part is shown by id (no weapon file is read here).
