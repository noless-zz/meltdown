## Summary

- New `game/core/sim_rules.gd` (`SimRules`, 106 lines): what a run fixes before its
  first tick and never changes afterwards. It holds the walls and their first box,
  the salvage rules, look-aim, aim assist and the part catalogue, with `set_walls`,
  `set_parts`, `set_salvage_rules`, `set_look_aim`, `set_aim_assist`, `part` and
  `part_ids`. Each setter takes `locked` (the run has started or a tick is being
  stepped) instead of reading `Sim`, so the class stands alone.
- `Sim` (259 lines) holds one `rules: SimRules`. Every public method keeps its name
  and signature and forwards; `walls`, `bounds`, `salvage_rules`, `look_aim` and
  `aim_assist` stay readable as read-only properties, so no caller changed. Nothing
  outside `core/sim.gd` wrote any of them. The walls moved too because they are the
  same kind of thing (unhashed, fixed for the run, rebuilt from the replay header),
  and without them `sim.gd` stayed above 260 lines.
- The parameter of `set_component_rules` and `set_rescue_rules` is now `p_rules`,
  so it does not shadow the new member; same type and position.
- Doc comments on a few untouched `Sim` members were shortened to fit the limit; no
  code in them changed.
- New `game/tests/test_sim_rules.gd`: 7 tests (defaults, each setter's valid, broken
  and locked case, sorted part ids, `Sim` reading through and locking after tick 0).
