## Summary

- `ComfortPresetFiles.CUSTOM_NUMBER` (5) is the custom mode's place in the cycle.
- `ComfortWiring` reads the custom file at `custom_path` once (`custom()`), so a rejected
  file is logged once by `ComfortCustom`, naming the field. `custom_available()` is true
  only for an accepted file. `next_number()` gives 1, 2, 3, 4, Custom, 1 with one and
  1 to 4 without. `set_preset(CUSTOM_NUMBER)` puts the custom preset where a numbered one
  goes, so the filter, cockpit, hit shake, refresh rate (through `main.set_comfort_preset`)
  and #791's swivel (which `set_preset` feeds) all read it. Without an accepted file it
  keeps the current preset and warns.
- `ComfortCustom.base` keeps the file's base preset.
- New `xr/comfort_switch.gd`: `--comfort=custom` or intent extra `meltdown_comfort=custom`,
  argument over extra, bad value ignored with a warning naming it. `main.gd` changes by one
  line (still 300). A custom launch starts the flight-test wiring `OFF`, like
  `--comfort-preset=`, so the saved choice does not override the switch.
- `ComfortChoice` accepts `"preset": "custom"` with `"custom_base": 1..4` (written only for
  the custom mode, rejected beside a numbered preset). `FlightTestWiring` restores it, or
  the base when the custom file is gone or now rejected, without overwriting the saved
  choice; a press into Custom saves it with the file's base.
