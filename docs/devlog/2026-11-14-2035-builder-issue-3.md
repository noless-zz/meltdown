# 2026-11-14 Builder: issue #3, Linux server and desktop builds in CI

First scheduled Builder run. Times in devlog file names are Israel time, as in the earlier
entries.

## Issue

#3 Export Linux dedicated server and desktop client in CI (ARC-6, DEV-8, PLT-4, MP-3).

## Summary

- `game/export_presets.cfg`: added `Linux Server` (dedicated server export mode) and
  `Linux Desktop`. Both are x86_64, embed the pack so each build is a single file, and
  exclude `tests/*` like the Quest preset.
- `tools/build.sh`: new `server` and `desktop` targets. The import, export and
  "was the file produced" check are now one shared function used by all three targets.
- `tools/smoke_server.sh`: runs the exported server with `--headless` for five seconds.
  It fails on a non-zero exit, and also on a logged `SCRIPT ERROR`, because Godot keeps
  running and exits 0 after one.
- `.github/workflows/ci.yml`: new `build` job that installs the Linux export templates,
  runs `tools/build.sh server` and `desktop`, runs the smoke test, and uploads
  `meltdown-server-linux` and `meltdown-desktop-linux`. The issue permits this edit.
- `game/tests/test_export_presets.gd`: three tests that the presets exist by the names CI
  uses, that only the server one is a dedicated server, and that no preset ships tests.

## Test results

Godot 4.7-stable and its export templates could be downloaded in this run, so everything
was run locally before pushing:

- 12 unit tests pass headless (9 existing, 3 new).
- `tools/build.sh server` and `tools/build.sh desktop` each produce a 71 MB binary.
- `tools/smoke_server.sh 5`: the server prints "Meltdown: running flat (no OpenXR
  session)" and is still running after five seconds.
- CI result: see the pull request.

## Open questions

- Both Linux builds are debug exports, like the Quest APK, so asserts and error messages
  stay on during development. Release exports can be added when a milestone needs them.
- The server build still starts the same `main.tscn` as the client and logs OpenXR loader
  errors because no runtime exists. That is harmless now; a server entry point that skips
  XR and the view layer belongs with the first `net/` work.
- Importing the project creates `*.gd.uid` files and `game/openxr_action_map.tres`, which
  are neither committed nor ignored. Godot 4.4+ expects `.uid` files to be committed. Not
  touched here because it is outside this issue; worth a small triage issue.
- The desktop client was not run: this environment has no display. It needs a quick look
  on a Linux desktop, or under the Windows export when that exists.
