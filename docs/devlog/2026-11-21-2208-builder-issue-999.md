## Issue

#999: trapped miners can be rescued in the simulation (CRW-1, SLV-3, ARC-1, ARC-2, ARC-4).

## Summary

- New `game/data/miners/rescue.json` (`rescue_reach` 4.0 m, `hold_seconds` 2.0 s,
  placeholders to tune). Both keys required; missing, unknown, non-numeric, non-positive or
  above the cap (50 m, 60 s) is an error naming the key.
- New `game/core/miner_rescue.gd` (`MinerRescue`, `RefCounted`): parses the rules, and the
  copy a sim owns holds the run state: miners still trapped (millimetres, as
  `LevelDef.miners`), ticks held at each, and `rescued`. `step` runs once per tick after the
  component pickups: a miner whose nearest-in-reach live ship has stayed within
  `rescue_reach` of it (centre to miner) for `round(hold_seconds * 60)` ticks in a row is
  removed and counted; a tick with no live ship in reach resets the count.
- `Sim.set_rescue_rules(rules, miners := [])` installs a fresh copy (so two sims sharing one
  rules object never share counts), only before the first tick. The issue named only the
  rules; the level's miners are a second, optional argument because the sim holds no
  `LevelDef`.
- `SimHash` joins `MinerRescue.state_hash` (rules, trapped miners with counts, rescued) only
  when rescue is on, so every existing hash stands.
- `SimEvent.Kind.MINER_RESCUED` appended (16); earlier numbers unchanged.
- `sim.gd` stays at 310 lines: the hooks are 6 lines, paid for by shortening 8 doc comments
  (and the outdated `run_seed` note that "nothing draws random numbers yet").
