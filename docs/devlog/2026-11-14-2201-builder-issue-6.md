## Issue

#6 Deterministic replay harness (ARC-1, ARC-2).

## Summary

- `game/core/ship_input.gd`: `ShipInput`, one ship's input for one tick. Thrust and turn
  are stored as whole thousandths, not floats, so a replay file holds exactly the numbers
  the simulation used and text cannot introduce rounding.
- `game/core/sim.gd`: `Sim` owns the `ShipState` list, the run seed and the tick counter.
  `step(inputs)` advances every ship by one tick and refuses a list that does not have one
  input per ship. `state_hash()` covers seed, tick and every ship.
- `game/core/replay.gd`: `Replay` holds seed, ship count, optional expected hash and the
  inputs of every tick; writes and parses the text format (`meltdown-replay 1`, `seed`,
  `ships`, `hash`, `inputs`, then one line per tick); `run()` replays into a fresh `Sim`.
  Malformed text is rejected with a line number.
- `game/tests/replays/basic_flight.replay`: 600 ticks, one ship, seed 20261114, expected
  hash 4190313060.
- `game/tests/test_sim.gd` (7 tests) and `game/tests/test_replay.gd` (9 tests).

`ShipState` is unchanged.

## Open questions

- The expected hash has only been produced on x86-64 Linux. ARC-2 asks for the same hash
  on the Quest (ARM). `ShipState.step` uses float trigonometry through `Basis.rotated`,
  which is not guaranteed to round identically on another CPU and compiler. Running
  `basic_flight.replay` on the headset and comparing the hash needs the self-hosted runner
  (#7); if it differs, the rotation maths needs a decision record.
- The seed is stored and hashed but nothing uses it yet, because the core draws no random
  numbers. The first random consumer should take a seeded generator owned by `Sim`.
- Input precision is now fixed at 0.001 thrust and 1 mrad/s turn. `xr/` and `net/` should
  build inputs with `ShipInput.from_floats` and simulate with the result.
- `Replay.save` and `load_file` use `FileAccess` inside `core/`. The layer rules do not
  list file access as forbidden; if the Reviewer prefers, they can move out and leave
  only `to_text` and `from_text` in the core.
- Still open from the #3 run: `*.gd.uid` files and `game/openxr_action_map.tres` are
  generated by import and neither committed nor ignored. Not touched here.
