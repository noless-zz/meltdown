## Summary

- `seed_card.gd --pick=N --fair`: before the greedy pick takes a seed it asks a flyer whether
  the bot escapes it. The default flyer, `SeedCard.bot_flight`, calls `M3SeedPick.fly` read
  only and returns the escape and the tick the run ended on. An escape means the reactor was
  destroyed first (`ExitRule.outcome`). A lost seed is remembered and the next best is tried;
  no seed is flown twice, and the two passes (unseen seeds, then any) share the flights.
- "Longest" under `--fair` means the longest escape the bot gets out of. It is found by
  flying the valid seeds longest first until one escapes (usually one or two flights). Using
  the range's longest regardless would leave "longest" uncovered whenever that one seed is an
  ambush. These flights are the only ones outside "the seed the greedy pick is about to take".
- Fair cards end with `"bot":"escaped","escape_tick":N`; the pick line ends with
  `"fair":true`. Exit 1 and the missing kinds work as before. `--fair` without `--pick` is a
  usage error (exit 2).
- Without `--fair` nothing changes: `--seeds=40` and `--pick=3` outputs were compared with
  `cmp` against `main`'s `seed_card.gd` and are identical.
- `tools/seed_card.sh`: usage line mentions `--fair`.
- Two new tests in `test_seed_card.gd` with an injected flyer: a lost seed is never picked
  and the next best is; the longest falls back to the longest fair escape; a range with no
  fair door names the door missing; only candidates are flown, each once; without `--fair`
  the flyer is never called and lines are unchanged.
