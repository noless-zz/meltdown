Built in an interactive session at the owner's request, right after the Builder run for

## Issue

#12 Publish the Linux server build and add a self-updating install script (MP-3, DEV-8,
ARC-6, DEV-10).

## Summary

- `.github/workflows/ci.yml`: new `publish-server` job. On a push to `main`, after
  `build`, it uploads the server binary and a SHA-256 file to the rolling pre-release
  `main-latest`. It is the only job with `contents: write`. The unit test job now also
  runs `bash -n` and `shellcheck` on `tools/*.sh`.
- `tools/install_server.sh`: installs or updates the server as a systemd service running
  as an unprivileged user, plus an hourly update timer. No secrets, no open ports.
- `docs/server-hosting.md`: VM settings, the install command, how to check the service.

## Test results

- 12 unit tests pass headless; `shellcheck` and `bash -n` pass on all three scripts.
- `install_server.sh` was run as root in the session's container against a local copy of
  the server build (`MELTDOWN_RELEASE_URL=file://...`) with `systemctl` replaced by a
  logging stub. First run: installs and restarts. Second run: no restart. New build:
  restarts. Wrong checksum: exits 1 and keeps the installed binary. Piped into bash:
  refuses. Run from its installed copy (the timer's path): works.

## Not verified

- The `publish-server` job only runs on `main`, so its first real execution is the merge
  of this pull request. If it fails, no release exists and the install script stops at the
  download with a 404.
- The script has not run under a real systemd, and not yet on the owner's VM. The unit
  files and the sandboxing options (`ProtectSystem=strict`, `StateDirectory`) are checked
  only by reading. The owner runs the install on the VM after the merge.
