## Summary

- New `HubWiring` (`game/hub_wiring.gd`). On the end screen's restart press, when the
  session has just ended the run (ship lost, or the last level escaped), it moves the run
  on exactly as the press always did (`RunWiring.after_session`: bank, crew, next run's
  seed) and opens a `HubPanel` on a `HubModel` built from the run's own profile and roles,
  the fitting store (cleaned with `FittingStore.valid_for`), the upgrade tree, the
  component files and the ship file.
- While open it takes the controls like the dev menu (decision record 0009): neutral
  ship input, right stick and A as named actions, and the view stays dark. Each craft
  saves the profile and each fit saves the fitting at once. The launch row saves both,
  closes the panel and `main.gd` flies the new run's level 1 with `restart_level(true)`
  (the run has already moved on), so the end screen's fade-in brings it up (CMF-8) and
  `RunShip` reads the fitting just saved. A refused launch shows `launch_check()`'s reason
  and stays.
- `--run` still starts straight into a run; single levels and escapes that lead to a
  shaft choice or the next level never open the hub. A rejected hub file logs one line
  and the next run flies as before.
- `main.gd` stays at 300 lines (a few comments shortened).
- Acceptance: new check `craft_and_fit` (`AcceptanceCraftAndFitCheck`) and m4 step
  `craft_and_fit`: run 12345 with a scratch profile banking 3 scrap alloy and 2 cell
  salts; the check opens the hub on the run, drives the stick and A through
  `apply_controls`, builds the first weapon offered (needle gun), mounts it in Primary 1,
  launches, and checks the run's level flies it and the scratch `user://` files hold the
  craft and fit. No pinned hash moved.
