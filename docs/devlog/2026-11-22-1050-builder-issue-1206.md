## Issue

#1206: choosing a menu row flies the ship, and the menu opens below the view.

## Cause

`DevMenuWiring.read` gave the ship neutral input only on frames that ended with
the menu still open. Two leaks:

1. A on a row that closes the menu (Close, Level, Restart level, Flight test, the
   update) closed it on the press frame; from the next frame the still-held A went
   to the ship as the afterburner, and a pushed stick as thrust. The owner's
   "selecting an item causes the ship to move forward".
2. A tap that closed the menu returned that frame's raw values, so a stick or
   trigger held across the tap flew the ship at once.

The menu itself was never placed: it hung at the rig origin, which is the floor of
the tracked space, so its rows were about 1.5 m under the eyes.

## Summary

- `dev_menu_release.gd` (new): `DevMenuRelease` notes every stick, trigger, grip and
  button held when the menu closes and reads each as idle until it has been
  released once; the menu button never latches.
- `dev_menu_wiring.gd`: the close frame returns neutral input and starts the latch;
  later frames pass through `release.filter`. `_toggle` places the menu at the
  rig camera's pose before opening (`head()`).
- `xr/dev_menu.gd`: `place` / `placement`: centre `distance_m` along the head's
  forward direction plus `offset_m`, facing the head, upright. Rows are centred
  on the menu's origin, so the middle row is at that point. `ORIGIN` is gone.
- `xr/dev_menu_spec.gd`, `xr/dev_menu.json`: optional `distance_m` (1.0) and
  `offset_m` ([0, 0]), validated.
