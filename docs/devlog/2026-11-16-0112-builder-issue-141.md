## Summary

- The four preset files gain `break_reminder_minutes`: 30 on presets 1 to 3, 0 (off) on 4.
  `ComfortPreset` declares it with a default of -1, so a file that leaves it out fails the
  new `validation_error()` (a finite number of at least 0).
- `ComfortPresetFiles.load_path()` loads and validates a preset file and returns null, with
  a warning naming the field, when it is rejected; `load_number()` goes through it.
  Godot turns text assigned to a `float` field into 0, which would read as "off", so
  `written_number_error()` also checks that the field is written in the file once, as a
  number. That text check runs only where a `.tres` file exists: exported builds hold the
  presets as binary `.res` without the text, and validate the loaded value only.
- New `game/xr/break_reminder.gd` (`BreakReminder`, `RefCounted`): `advance(seconds,
  flying)`, `due()`, `acknowledge()`, `set_enabled()`, `set_preset()`. Only flying time
  counts; a preset change keeps the time flown; a 0-minute preset or switching off clears a
  pending prompt. Switching back on starts a fresh interval (a choice the issue left open).

## Test results

Godot 4.7.2-stable, run locally exactly as CI does: 460 tests, 0 failed. New file
`test_break_reminder.gd` (11 tests); `test_comfort_preset.gd` table extended with the field.
Mutation checks: counting paused time fails `test_paused_time_does_not_count`; dropping the
written-number check fails `test_invalid_value_rejects_the_preset_file` (the text case).

The first CI run failed in "Linux server and desktop": the exported build had no `.tres`
text, so every preset was rejected and `main.gd` read a null preset. Fixed by limiting the
text check to `.tres` files that exist, with `test_binary_preset_is_validated_by_value`
covering a saved `.res` preset. Unit tests had passed, since they read the source files.
