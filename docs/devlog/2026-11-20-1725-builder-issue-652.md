## Summary

- New `ControllerAnchors` (`game/xr/controller_anchors.gd`) and data file
  `game/xr/controller_anchors.json` (ARC-4). While a runtime model is shown, each leader ends on:
  1. the model's own named part (a node, or a skeleton bone for skinned glTF models), searched by
     the name lists in the data file (`b_thumbstick`, `b_button_a/b/x/y`, `b_button_oculus`,
     `b_trigger_front`, `b_trigger_grip`, and looser variants; exact names first);
  2. otherwise the per-profile offset table, keyed by interaction profile; a profile the table does
     not know (or none) uses `runtime_default_profile`, the Quest 3 Touch Plus;
  3. the generic shape keeps today's `CONTROL_POINTS`.
- `ControllerModel` keeps the last labels and re-places the lines when the Meta model loads or an
  `XR_EXT_render_model` model arrives or goes, and reports `anchor_source()`.
- While a runtime model is shown, one `MELTDOWN_LABEL_ANCHORS hand=... source=... parts=...` line
  goes to the log per change, so a logcat shows which parts the Quest model names.
- Physical controls never swap, so the default, left-handed and paired layouts only change the
  text on each control; the lines follow automatically.
