## Summary

- New `game/gen/loop_bridges.gd` (`LoopBridges`): reads `game/data/gen/generator.json`
  (`loop_min_m` 6, `loop_max_m` 120, `loop_max_count` 2). An unknown key is named; otherwise
  every missing key is named; bad values are rejected.
- After the chain is placed, `MineGenerator.generate(seed, modules, count, bridges)` looks at
  pairs of open connectors, lowest index first. A pair is bridged when the two have the same
  size class, face each other on one line and are within the gap range. A bridge is a tunnel
  box with the connector's square plus a doorway box at each end. The tunnel may overlap no
  placed box. Each doorway may overlap only the boxes of its own module. Bridged connectors
  leave the open list, and one is always kept for the start. `MineGenerator.loops` counts the
  bridges. Without `bridges`, the level is the same tree as before.
- `MineGenerator._door` and `_add_box` are now public as `door_for` and `add_box`, because
  `LoopBridges` uses them.
- `SeedSweep.run` (the 1,000-seed validator test and `validate_seeds.gd`) builds levels with
  the shipped loops. It counts `looped` seeds and fails every seed if `generator.json` is
  broken.
- Pinned hashes changed: 0. No test pins a generator `output_hash`. Callers without
  `bridges` are unchanged.

## Loop rate (criterion not met)

3 of seeds 0..999 have a loop (0.3%), and 21 of 0..9,999. The issue asks for 20%. Data
cannot fix this: with `loop_min_m` 1, `loop_max_m` 1000 and `loop_max_count` 10, the rate is
still 3 in 1,000. Of 562 opposite-facing open pairs in 1,000 seeds, only 3 lie on one line. The
data values were chosen for sensible tunnels (6 m lets the two 3 m doorways meet; 120 m is
above the longest gap bridged in 0..9,999, which was 69 m), not for the rate. Follow-up #411 (`triage`)
lists ways to raise the rate.
