## Summary

- The issue offered two ways: cull the mine and the fade, as the home base room does, or
  raise the controllers above the fade by render priority. The cull way would also have hidden
  the end screens' words, the shaft panel, the menu and the aim ray, which are all on the
  mine's layer. Each would have needed the extra layer, touching files in other lanes. This
  run uses render priority, as the aim ray and the screens' words already do.
- New `xr/hands_over_fade.gd` (`HandsOverFade`): while raised, every drawn surface of both
  controllers gets a copy of its material. The copy is in the transparent pass, at the top
  priority (one above the fade), and keeps its depth test. The opaque ones use the depth
  pre-pass. Labels are skipped. This covers the generic shape (`material_override`) and the
  runtime and Meta models (per-surface overrides of the glTF's own materials). Lowering puts
  every original back. Raising repeats each frame while dark, because a runtime model's meshes
  can arrive late. Surfaces already raised are skipped.
- `DestroyedWiring` holds one and calls `hands.update(end_screen_up())` beside the panel
  cover. `end_screen_up()` already covers both end screens and the open shaft panel.
  `reset()` lowers them.
- `view/fade_overlay.gd`: the fade's priority is now the named constant
  `FadeOverlay.RENDER_PRIORITY` (same value, `MAX - 1`).
- `escape_end_wiring.gd`, `shaft_choice_wiring.gd`, `main.gd` and the controller files are
  unchanged.

## Open questions

- With the depth test kept, a hand held below the dash stays hidden at these screens. That
  is the "not through the cockpit" rule. It is worth a look in the headset.

  on the Quest's own model.
