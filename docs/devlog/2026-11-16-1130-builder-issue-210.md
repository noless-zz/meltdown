## Summary

Scope as narrowed by the owner and the Planner: items 2, 3 and 5 (no root-cause hunt).

- `tools/update_quest.sh` and `tools/update_quest.ps1` behave the same:
  - An `adb install -r` failure whose output has no `Failure [...]` part prints
    "adb gave no reason; trying once more with --no-streaming..." and retries once with
    `adb install -r --no-streaming`.
  - A failure with a `Failure [...]` part is not retried. The signature-mismatch advice
    and `--uninstall-first` / `-UninstallFirst` flow from #104 are unchanged; the install
    after the uninstall goes through the same retry rule.
  - Every reported failure prints adb's text indented, then either `Reason: Failure [...]`
    or "adb gave no reason.", then `To try by hand: adb -s <serial> install -r "<path>"`.
  - After such a failure the temporary download is kept (and the script says where), so
    the manual command points at a file that still exists. On success it is deleted as
    before.
- Stub adb (`tools/fixtures/update_quest/bin/adb`): `STUB_ADB_BLANK=always|streamed`
  fails installs with an empty reason, like the owner's log; `STUB_ADB_INCOMPATIBLE=sticky`
  keeps failing after the uninstall.
- `tools/test_update_quest.sh`: four new checks plus one extra assertion; the script's
  `TMPDIR` now points into each scenario so kept and removed downloads can be checked.
