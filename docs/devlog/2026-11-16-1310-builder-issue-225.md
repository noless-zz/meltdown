## Summary

- `RobotState` gains `weapon` (a resolved `WeaponDef`, null for an unarmed robot) and
  `fire_cooldown`. `fire_at(target)` counts the interval down and fires when the target
  is within `weapon_range()` (speed × lifetime) and within `FIRE_CONE_HALF_ANGLE_DEG`
  (10°) of the facing. No energy pool. Weapon and cooldown join the robot hash only on an
  armed robot.
- `Sim.spawn_robot` takes an optional `weapon`; core still opens no files. Robots fire
  after they move, from their centre along their facing, like ships.
- Robot shots carry `owner_index = -1 - robot_index` (`Projectile.robot_owner`,
  `is_robot_owned`), reusing the hashed field so existing projectile hashes stay. They
  hit live ships through the same segment test as #205 (moved to the static
  `Projectile.segment_entry`; `RobotState.segment_entry` delegates), never robots. Ship
  shots still never hit ships.
- No ship-hit event existed (only `WALL_IMPACT`), so `SimEvent.Kind.SHIP_HIT` was added:
  ship hit, damage, shot direction. `HitShake.feed` now shakes for it too, scaled by a new
  `full_hit_damage` key in `game/xr/hit_shake.json` (16, two pulse cannon shots). The
  roll side reads from the shot's direction of flight exactly as from a wall normal.
