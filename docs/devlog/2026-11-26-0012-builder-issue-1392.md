- `tools/device_acceptance.ps1`: the fallback is `com.godot.game.GodotAppLauncher`, the
  only exported activity. A start refused as "not exported" (`SecurityException`) is tried
  once more with the launcher; a refused launcher fails as before, with no loop. A start
  whose output holds `Exception` now also counts as failed. New `-ResolveRetrySeconds`
  (default 1).
- `tools/acceptance_headset.ps1`: `Resolve-GameActivity` asks
  `cmd package resolve-activity --brief` up to 3 times, about 1 s apart, and says why it
  fell back ("the activity lookup printed no activity on all 3 tries" or "failed");
  `Test-NotExported` recognises the refusal. Kept here so `device_acceptance.ps1` stays
  under 300 lines. There is no shared copy of the fallback in `acceptance_common.ps1`.
- Stub adb: the lookup follows a sequence (`ok`, `empty`) and names the launcher by
  default, as the headset did on the runs that worked; `am start` can refuse an activity
  as not exported, with the text Android printed on the owner's run.
- `docs/install-on-quest.md`: the view-log command started `GodotApp` too; it now starts
  the launcher.
