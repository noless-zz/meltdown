## Summary

- `.github/workflows/device-acceptance.yml`: manual dispatch (input `suite`, default
  `all`) and a nightly schedule only; every job limited to `main`. Three jobs:
  - `headset` on `[self-hosted, quest-pc]` runs `tools/device_acceptance.ps1`: skips
    cleanly with a notice when `adb devices` lists no headset; downloads
    `meltdown-quest-debug.apk` and its `.sha256` from `main-latest` and refuses a
    mismatch; `adb install -r`, retried once with `--no-streaming` when adb gives no
    reason (as #210 asks for the update script); keeps the headset awake
    (`stay_on_while_plugged_in`, proximity sensor) and restores both afterwards; starts
    the game with `--es meltdown_acceptance <suite>`; waits for
    `Meltdown: acceptance: exit <n>` in logcat with a timeout, taking a screenshot every
    30 s; cuts the reports from between the `MELTDOWN_ACCEPTANCE_BEGIN/END` markers;
    writes `result.json`, one JSON per suite, screenshots and `device.log`; fails on a
    failed step, a missing report or a non-zero exit.
  - `simulator` on the same runner after it runs `tools/simulator_acceptance.ps1`
    from source: import, then the game windowed with `--acceptance=<suite>` and
    `--log-file`. Skips with the reason when not on Windows, when the runner is a
    service (session 0), when the active OpenXR runtime is not the simulator (printed
    either way), or when Godot 4.7.2 is not found (`PATH` or the `GODOT_PATH`
    repository variable). Screenshots of the primary screen.
  - `report` on `ubuntu-latest` (so the `issues: write` token never reaches the PC)
    runs `tools/post_acceptance.ps1`: one table with a Headset and a Simulator column
    in the job summary; on a scheduled run it replaces its comment on the open gate
    issue of the earliest open milestone and opens or comments on one `playtest`
    regression issue naming the failing suite and step.
- `tools/acceptance_common.ps1`: the shared report parsing, verdict and table code.
- CI: `tools/check_device_workflow.sh` (YAML parse; triggers exactly dispatch and
  schedule; PC jobs on `[self-hosted, quest-pc]`, limited to `main`, no extra token
  permissions; every `tools/*.ps1` parses) and `tools/test_device_acceptance.sh` (stub
  adb, nine scenarios), both in the `test` job.
- `docs/licences.md`: Meta XR Simulator, installed by the owner, not vendored.
