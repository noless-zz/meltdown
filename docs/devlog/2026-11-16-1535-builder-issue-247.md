## Summary

- New `game/net/net_host.gd` (`NetHost`) and `game/net/net_client.gd` (`NetClient`):
  `RefCounted`, `ENetConnection` used directly, no nodes, nothing runs until the caller
  calls `poll()`. `start(0)` asks the system for a free port; a failed bind returns the
  error and sets `error` rather than retrying.
- Handshake: the client sends `hello` when ENet connects. The host answers every hello
  with its own (so a refused client can name the host's version and build), then refuses a
  mismatched protocol with ENet disconnect data `REFUSED_PROTOCOL`. Also `REFUSED_FULL` and
  `REFUSED_NOT_HELLO`. The client sets `refusal` naming both versions.
- Lockstep: the host owns the only authoritative `Sim` (one ship per client, given out in
  accept order) and steps tick `t` only once every client's input for `t` is in. It then
  relays each ship's applied input for `t` to every client and, at every multiple of
  `HASH_INTERVAL` (60) ticks, its state hash. The host takes the ship index from the
  connection, not the packet. Inputs more than `MAX_INPUT_LEAD` (120) ticks ahead, or for
  past ticks, are dropped.
- The client sends up to `INPUT_LEAD` (3) ticks ahead of its own sim, steps only from
  relayed inputs, and compares hashes whichever side's arrives first; a mismatch goes to
  `desyncs` as `{tick, host_hash, client_hash}`.
- `local_session.gd`, `net_messages.gd` and `core/` untouched.

## Open questions

  host and clients are built from the same values by the caller, and a client sends ship

  the hub or mine generator needs it.
- A client that disconnects mid-game stalls the host (its inputs never arrive); the host
  only reports it in `error`. Dropping or replacing a ship is M5's co-op work.
- Turn rates from clients are still not capped (see the #244 entry).
