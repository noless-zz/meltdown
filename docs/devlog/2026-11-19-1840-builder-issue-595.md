## Summary

- `game/meta/installer_probe.gd`: `run_steps(bridge, emit)` runs source, target, copy, content
  URI and intent in order and logs one `MELTDOWN_INSTALLER_PROBE` line per step. A failing step
  stops the run with `error: <step>: <reason>`, the reason being the exact Java exception when
  one was thrown. A copy shorter than the source is an error. The old `FileAccess.file_exists`
  and `DirAccess.copy_absolute` are gone. Request handling and the debug-build guard are
  unchanged, so the same `adb` lines start it.
- New `game/meta/installer_probe_bridge.gd`: one method per Android call, so the steps can be
  tested with a fake. The base class fails every step.
- New `game/meta/installer_probe_java.gd`: the real bridge, `JavaClassWrapper` only. The source
  is checked with `java.io.File` (exists, canRead, length) and copied with
  `Files.copy(Path, OutputStream)` into a `FileOutputStream` in the files directory. A read loop
  would not work because a `byte[]` passed from GDScript is a copy. URI and intent are built as
  in #130.
- No permission change: `REQUEST_INSTALL_PACKAGES` is already in the Quest preset.
