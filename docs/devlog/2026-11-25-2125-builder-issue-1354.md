## Summary

- `LocalSession.fly_ships(header, sources)`: a session flies every ship of a replay header
  with no ticks yet, ship 0 from its own source (the local view) and ships 1 and up from
  one source each, with no network. The sim is the header's own `Replay.run`, so the live
  flight and the recorded replay are the same run (ARC-2). Each tick records all inputs.
- `net/other_ships.gd` (`OtherShips`): the other ships' sources and their copies before
  and after the latest tick, read through `LocalSession.previous_others()` and
  `current_others()` (empty for one ship). Copies only (MP-2).
- `ReplayInputSource` takes a ship index; a replay of more than one ship builds its
  session with `fly_ships`, a source of the same replay per extra ship.
- The runner flies a multi-ship replay on a plain replay step
  (`AcceptanceStepLevel.flies_ships`); a seed or controls step still refuses one.
- `view/other_ships_view.gd` (`OtherShipsView`, node `OtherShips`): one `ShipModel` of the
  shipped look per other ship, blended between ticks like the robots, engine glow from
  speed (full on the afterburner), hidden when destroyed or escaped. No light, no
  simulation object. `CombatWiring` adds it and feeds it the session's copies each frame.
- The step's replay `stress_scene.replay` now holds all four ships
  (`StressScene.replay(5600)`); the step's hash is 1956914250 (was 1601082185 for ship 0
  alone). The `stress_scene` check fails unless 4 ships were flown and 3 are drawn, and
  reports "4 ships flown, 3 drawn beside the local one".
