## Summary

- `ComfortPreset.look_aim` (new "Aim" row): on in `comfort_anchored.tres` and
  `comfort_guided.tres`, off in `comfort_pilot.tres` and `comfort_unrestricted.tres`.
- Custom mode follows presets 3 and 4: `ComfortCustom` sets `look_aim` off on every base
  and lists it in `NOT_SETTABLE`, so a custom file naming it is rejected as an unknown field.
- New `xr/look_aim_head.gd` (`LookAimHead`; not `look_aim.gd` as the issue suggested,
  because `core/look_aim.gd` already holds `LookAim`): the rig camera's forward, turned into
  ship space by the `HeadRecentre` offset, becomes `ShipInput.aim_q`; off, or with the head
  untracked, the aim is the nose. An input already on the nose is handed back unchanged.
- `ComfortWiring` hands the preset to it in `_init` and `set_preset` (so the button, the dev
  menu and a mid-run change all apply from the next input), attaches it with the swivel,
  and runs it first in `hand_input`. Only the input changes.
- New `view/aim_reticle.gd` (`AimReticle`) and its look `view/aim_reticle_look.json`
  (`AimReticleLook`): a ring 25 m out along the ship's `gun_direction`, world-locked,
  drawn over walls, shown only while look-aim is on. `CombatWiring` places it under the
  world node; `main.gd` passes `comfort.look_aim.enabled` to `combat.update` (same line count).
