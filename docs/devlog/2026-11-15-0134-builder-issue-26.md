# 2026-11-15 Builder: issue #26, the XR path in CI on Monado's simulated headset

Scheduled Builder run. Its stored prompt named issue #26 and said to skip steps 2 and 3

## Issue

#26 Experiment: run the VR code path in CI with Monado as a simulated headset
(PLT-2, ARC-1, DEV-3).

## Result

Works, with limits. A hosted runner starts the game in real OpenXR mode on Monado's
simulated headset: session begun, 2 views, 20 Hz. The full result, the set-up and the
limits are in `docs/decisions/0002-monado-in-ci.md`.

## Summary

- `.github/workflows/ci.yml`: new job `XR smoke test (Monado)` as a separate block at
  the end. No `needs` in either direction. The issue permits this edit.
- `tools/xr_smoke.sh` (new): starts `monado-service` with the null compositor, runs the
  game under Xvfb on lavapipe with the Mobile renderer, and fails unless the result line
  reports a session with at least 2 views.
- `game/xr/xr_smoke_probe.gd` (new) and `game/main.gd`: `--xr-smoke-frames=<N>` after
  `--` makes the game quit after N frames and print one `MELTDOWN_XR_SMOKE {json}` line.
  Without the flag `_process` is off and nothing changes.
- `game/tests/test_xr_smoke_probe.gd` (new, 6 tests).
- `docs/decisions/0002-monado-in-ci.md` (new) and three CI-only tools in
  `docs/licences.md`.

## Test results

Godot 4.7-stable, Monado and Docker were available in this run, so everything was run
locally before and between CI runs.

- 50 unit tests pass headless (44 before, 6 new), run exactly as CI does.
- `shellcheck tools/*.sh` is clean.
- CI attempt 1 (run 43652355148): the four existing jobs passed; the new job failed.
  A session started, then Godot crashed with signal 11 in a rasteriser thread.
- The crash was reproduced in an `ubuntu:26.04` container and narrowed down: Mesa 26.0.8
  lavapipe, three or more threads, Forward+ renderer, stereo. The table is in the
  decision record. The script had selected Forward+ by mistake; it now names the Mobile
  renderer and pins one lavapipe thread.
- CI attempt 2 (run 43653672259): all jobs green. The new job took 88 seconds in total
  and printed
  `MELTDOWN_XR_SMOKE {"frames":120,"refresh_rate":20.0,"runtime":"Monado(XRT) by Collabora et al '25.0.0+dfsg-2build1'","session":true,"views":2}`.
- CI attempt 3 is the run for this devlog commit; see the pull request.

Two of the six allowed CI attempts were needed for the code.

## Open questions

- `ubuntu-latest` now installs Monado 25.0.0 and Mesa 26.0.8, the versions of Ubuntu
  26.04. The job follows the runner image, so a later image can break it again. The
  decision record says what to do then.
- The new job is not `continue-on-error`. Whether it should block merges is the owner's
  choice; it must not be added to the required checks (issue #26).
- Any desktop start with `--rendering-driver vulkan` and no `--rendering-method` runs
  Forward+, not the project's Mobile renderer. Worth remembering for other scripts.
- Godot logs `XR_ERROR_SESSION_NOT_STOPPING` at quit because the game does not ask the
  session to end first. Harmless here; not checked on the Quest.
- The simulated headset has no controllers and only 20 Hz, so hand tracking and the
  90 Hz branch are still only checked in the headset.
- Still open: `*.gd.uid` files and `game/openxr_action_map.tres` appear after import and
  were left uncommitted here (#18). This pull request adds two more scripts without
  `.uid` files; whoever merges #29 after this one has to add them.
- #19 also edits `ci.yml`. This job is appended at the end of the file; if #19 appends
  there too, the second pull request to merge needs a rebase.
