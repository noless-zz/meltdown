## Summary

- `data/hub/hub.json` gains an optional `fit_ship` section: the ship's outline seen from above
  (nose to +x), where each slot sits on it, slot size, pick radius, hull colour, and how many
  rows show while a slot is being picked (1). `meta/hub_fit_layout.gd` parses it and names the
  key at fault; `HubConfig` keeps it as `fit_layout`. A file without the section keeps the
  bay's rows only.
- `meta/hub_fit_bay.gd` (`HubFitBay`) is the fit station's screen model as `HubText` rows.
  With no slot chosen there is one row per slot, then the strip row, then #1357's summary.
  Pressing a slot that can take something chooses it. A chosen slot shows its name, then its
  mount, move and back-to-stock rows, with the highlighted item's before and after under it.
  An item fitted elsewhere is offered only as a move (#1336). It also gives the drawing as
  data: slots with positions, the icon of what each holds (weapon or module by what it
  grants, ship parts by family, the ship file's own weapon by id), the selected one, and an
  icon per item row.
- `HubFitRows` now exposes `slot_line`, `choices` and `strip_rows`, used by both the flat
  panel's page (unchanged rows) and the bay.
- `HubText`: `fit_slot`, plus `back()`, `slot_at()`, `point_slot()` and `drawing()`. Pressing
  a slot row chooses it. A successful fit or move returns to the ship with the filled slot
  selected. Pressing still calls `HubModel.fit`, `move` and `strip`: the same code paths as
  before (ARC-3, MP-2).
- `xr/hub_fitting_view.gd` (`HubFittingView`) draws that data on the station's screen. The
  hull is a flat unshaded polygon. Each slot shows its `HubIcon` or an empty ring, and the
  selected slot gets a second, larger ring in the frame colour, so the selection is a shape
  and not only a colour. While an item is being chosen, the ship hides and each item row
  gets its icon at the face's left edge.
- `HubStationScreen.shown_rows()` says where each row line sits. `HubStations` draws the hub
  text's `drawing` on the station in use. Stick left calls `back()` before leaving the
  station. Inside the bay the aim ray picks the slot it newly reaches, like station picking:
  the first version re-selected on every frame and undid stick steps, which the `ship_summary`
  step caught.
- Acceptance: the shared `press_in_station` helper takes a fit's slot first, as a pilot does.
  `ship_summary` accepts its stock line as the marked selected row, because the slot picker
  leaves room for one row. A new `fitting_ship` step in `suites/m6/base.json` (check
  `acceptance/checks/fitting_ship_check.gd`) builds a weapon, checks the ship draws every
  slot, and takes a screenshot. It then opens Primary 1's list, checks there are item icons
  and no more than five rows, and takes a second screenshot. Finally it mounts the weapon and
  checks the save and the ringed icon. Screenshots are skipped headless.
