## Summary

- `status_panel_look.json` gains an optional `corners` object: `top_left`, `top_right`,
  `bottom_left`, `bottom_right`, each the panel's centre from the eye point. A panel in a corner
  is turned to face the eye with its rows level, so no tilt per corner is needed. Shipped: about
  17 degrees to the side and 13 up or down, 0.55 m out like today's place. Bad values are named
  (missing or unknown corner, under 0.2 or over 0.9 m, not ahead of the eye).
- Today's place is not mapped to a corner: it stays the default under the name `centre`, built
  from `position_m` and `tilt_deg` exactly as before, and `--panel=centre` returns to it.
- New `xr/panel_corner.gd` (`PanelCorner`): the chosen corner in `user://meltdown_panel.json`
  (one field, `corner`), `choose()` for the switch now and the menu later, `--panel=` or the
  `meltdown_panel` intent extra read like `--level`. An unknown name is ignored with one warning.
  A missing or broken file gives `centre`. `PanelCorner.current` is what `rig_transform` reads.
- The placement code moved out of `status_panel.gd` into `StatusPanelLook.placement`
  (294 lines now). `RigViews.add_status_panel` reads the corner, so `main.gd` is untouched.
