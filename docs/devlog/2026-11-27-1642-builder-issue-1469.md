## Summary

- New data file `xr/base_labels.json` with its loader `xr/base_labels.gd` (`BaseLabels`):
  stick "step", A "select / launch", left menu "tap: menu". A bad key, an unknown control or
  an empty text names its field (`labels.right_paddle`) and leaves no labels there, never the
  flight ones.
- The file is beside `xr/layouts/`, not in it as the issue suggested: every JSON file in that
  folder is read as a flight layout (the clearance tests list them as schemes).
- `XRRig.refresh_labels` shows these labels while pointing selects, which it reads from the
  aim ray's own `AimTargets.find`. It checks each frame and rebuilds when the place changes.
  In flight it builds the flight labels exactly as before.
- `ControlLabelSet.set_at_base`: at the base and the shaft choice, labels and leaders also go
  on `HubRoom.HANDS_LAYER_BIT` and to the top render priority (text at MAX, outline one
  below), so the room's camera draws them and they sit above the shaft choice's fade. In
  flight the layers and priorities are Godot's defaults again.
- `HandLayer` still skips the label set; only its comment changed.
- No trigger label: nothing at the base or the shaft choice reads the trigger as a select
  (`DevMenuWiring.actions` maps the right trigger to the dev menu's seed step only).
- Left-handed mode: the base and the shaft choice read the right stick, A and the right aim
  in both hand modes. Mirroring would label controls that do nothing there, so the shipped
  file sets `mirror_left_handed` to false. The mirror (menu stays on the left, as the reset
  hold does) is built and tested. #1496 (triage) asks whether those controls should swap.
