## Summary

- **Why `focus_pause` hung on the device:** `AcceptancePauseCheck` compared the camera's world
  pose on every held frame. On the Quest that camera follows the player's head, so the first
  held frame already counted as "the camera moved". The bigger bug: once a held frame had a
  fault, `after_frame` returned early and stopped counting held frames. The resume waits for
  that count, so it never came, and the session stayed paused for good. The replay never
  reached its end, and the runner waited until the script's 15-minute limit killed it.
  Headless, the camera never moves, so CI never saw this. I reproduced it headless by swaying
  the camera each frame on the old code: it stayed at tick 300 of 600 for 3000 frames.
- **Fix:** every held frame now counts, faulted or not, and the first fault is still kept for
  the verdict. The pause always ends after its frames, without waiting for any OpenXR event.
  Held frames now compare the rig's pose (`rig_pose`), where the game places the cockpit,
  instead of the tracked head inside it.
- **`view_not_flat`:** the message, pass or fail, now gives the luminance stddev range and
  median, the colour-count range, and both thresholds. The same numbers go into the
  measurements. The verdict is also printed as a `Meltdown: acceptance:` log line, so a later
  hang cannot lose it again.
- **New m1 step `no_stale_overlay`** (check file `acceptance/checks/stale_overlay_check.gd`),
  after `comfort_hits_preset_4` and before `focus_pause`: it restarts the flight and flies 3 s
  of idle frames. After a 1 s grace, any frame with no pause, reset fade, end screen, dev
  menu, base or launch fade, hit or turn in progress must show the fade quad, the base room's
  launch fade, the vignette and the hit-flash strips at 0 opacity. A failure names the
  overlay and its opacity. `HitFlashOverlay.opacity()` (read only) was added for it. The
  game has no separate pause dim.
- **The brown veil:** I could not see the owner's screenshots; they are on his PC. The code
  has no pause dim, and every full-view overlay is set again from its source on every frame,
  so none of them is a likely veil. The owner's report on #1459 points to the cockpit glass,
  which this issue leaves to #1459. I do not know why the world was missing in `50-0434s`
  during the hang. `no_stale_overlay` now runs right before `focus_pause` and will name any
  overlay that is still on.
