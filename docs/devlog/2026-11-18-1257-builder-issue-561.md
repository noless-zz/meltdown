# 2026-11-18 Builder, issue #561 (lane-c)

Scheduled Builder run in lane-c. Named in Israel time (UTC+2).

## Issue

#561 Map hologram re-clamps its zoom when the look file changes (MAP-1, ARC-4). No open
pull request closed a lane-c issue, so there was nothing to fix first.

## Summary

- New `MapLook.load_file(path)` reads and parses a look file and returns
  `{"look", "error"}`: the parsed look and `""`, or `FALLBACK` and an error naming path and
  field, after the same warning as before. The file read, fallback and error text moved
  there from `MapHologram.load_look`.
- `MapHologram.load_look` now applies the result and calls `set_zoom(_zoom)`, so the zoom
  is clamped to the look now in force and the lines, ship marker, exit and reactor markers,
  route and fire markers are re-placed at once. Accepted and rejected files both do this.
- The two `_init` lines that hid the exit and reactor markers are gone: `load_look` now
  places the markers, which hides both until `set_markers`.
- `map_hologram.gd` went from 297 to 280 lines (the look loading, the two `_init` lines
  and tighter doc comments). Public API unchanged. No `core/`, `gen/` or `net/` change.

## Test results

- Godot 4.7.2-stable headless in the run's scratch space, `--import` then `run_tests.gd`:
  1528 tests, 0 failed. Five are new in `test_map_look_reload.gd`: a narrower look clamps
  3.0 to 2.0 and moves every marker by 2/3 without a `set_zoom`; a rejected look clamps to
  the built-in limits; a look whose limits hold 1.5 leaves zoom and markers unchanged;
  `load_file` on a missing, rejected and accepted file; the shipped look keeps zoom 1.0.
