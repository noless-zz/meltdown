## Summary

- New `xr/foveation_keep.gd` (`FoveationKeep`): a change from the menu is applied at once
  through `FoveationSwitch.choose`, as before, and starts a `keep_seconds` timer. Holding A
  for `hold_seconds` keeps it. The press of A that chose the setting does not count: A has
  to be released and held again. When the timer ends, or the menu closes, or focus is lost
  before the confirm, the setting from before the change comes back through `choose` with
  source `revert`. A second change while waiting keeps the setting from before the first as
  the one to go back to, and restarts the timer. Pressing A again on the setting already
  chosen is not a change, so the keep hold can start on the Foveation row.
- New data file `xr/foveation_keep.json` and loader `xr/foveation_keep_spec.gd`:
  `keep_seconds` 15 (5 to 30), `hold_seconds` 1.5, three tones and three pulses. A rejected
  file keeps the built-in values, because dropping the revert would leave a broken picture
  stuck. The warning names the bad field.
- New `xr/foveation_keep_cue.gd`: under the rig's camera, so each tone comes from the head.
  The tones are sine sweeps built in code (low flat, rising, falling), so there is no sound
  file and nothing to add to `docs/licences.md`. Each tone comes with a pulse on both hands
  while an XR session runs.
- `FoveationSwitch.choose` takes a source (`menu` by default, `revert` for the keep).
- `DevMenuFoveation` owns the keep and cue. After a revert, the open menu shows the setting
  back in use. It connects the OpenXR `session_visible` signal (focus lost) to the revert
  itself, because `main.gd` is at its 300-line limit, which two tests enforce.
- `DevMenuWiring.read` passes A, whether the menu is open, and the steady clock each frame.
