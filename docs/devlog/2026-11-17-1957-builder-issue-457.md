## Summary

- `MeltdownDebris` entries may give `size` (`[x, y, z]`, full extent in metres, each at
  least 0.1, held as whole millimetres in `sizes_mm`) instead of `radius`. Exactly one of
  the two is required; both, neither, a short list or a side below 0.1 are named with the
  entry's index. A box keeps `radii_mm` at 0; a missing `sizes_mm` entry means a sphere, so
  `gen/` code that appends spheres needs no change.
- New `core/debris_shapes.gd` (`DebrisShapes`) holds the shape tests: sphere and box
  segment entry, and push-out for both. The sphere code moved there unchanged. A box
  push-out uses the nearest point on the box (face hits match a wall, edges and corners
  a sphere); a ship whose centre is inside leaves through the nearest face.
- `to_json` writes `size` for boxes and keeps the old key order, so sphere-only lists
  write, parse and hash exactly as before. The replay's debris line round-trips boxes.
- `sim.gd`, `gen/` and `net/` were not edited. Route guard, opening clearance, map route,
  bot escape and the view still treat a box as a zero-radius point; that is #458 and #459.
