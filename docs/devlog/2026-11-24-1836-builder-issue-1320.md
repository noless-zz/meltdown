## Summary

- `xr/shaft_panel_shapes.json` (`ShaftPanelShapes`): a `look` key per shaft kind
  (`steady` → lift, `deep` → drop, `hot` → vent). Each look is a short label and a list
  of primitives (box, cylinder, sphere, prism) with size, place, turn and colour, drawn in
  file order. There is also one gauge per thing a shaft changes (robots, alarm, finds),
  each with its own min..max scale and a baseline mark, plus layout lengths and colours.
  Every word is checked against `label_max_chars` (24).
- `ShaftPanelGauges`: the gauges come from the modifiers the model already read. Robots
  and alarm use the risk multipliers, finds uses the mean tier of `tier_weights`. The
  value shown is "x1.3" or the existing reward words ("rare finds").
- `ShaftPanelCard` draws a plate, the look's object, the label and the gauges. All of it
  is unshaded and draws over the fade quad without depth test, ordered by
  `sorting_offset`. A shaft with no look shows its full label and risk line instead.
- `ShaftPanel` puts the shafts side by side when they have looks. "Suspend run" sits
  `suspend_gap_m` below the plates, and with no shapes the panel is today's text rows.
  The title moved from 0.24 m to 0.30 m above the eye to make room.
- Choosing: stick up/left and down/right step (down still steps, so the m4 replays are
  unchanged). Pointing the right controller's aim at a shaft or row highlights it, using
  the hub's `HubStations.pick`. A still hand does not undo a stick step. Nothing moves the
  pilot.
- Acceptance: `shaft_choice_look` in `suites/m6/effects.json`, check file
  `acceptance/checks/shaft_choice_look_check.gd`. `AcceptanceRunStep.begin` now gives
  that step's run the shipped shafts, as it already did for `shaft_choice`. This is a
  one-line change to a shared acceptance file.
