## Issue

#976: destroyed robots drop components in the simulation; the ship collects them by flying
through (CRF-1, ARC-1, ARC-2, ARC-4). Prerequisite #925 has merged.

## Summary

- New `core/component_item.gd` (`ComponentItem`: kind id, count, position, velocity) and
  `core/component_pickup.gd` (`ComponentPickup`): the pickup rules parsed from new
  `data/components/pickup.json` (`pickup_reach`, required, errors name the key), the drop
  roll, the per-tick `drop` and `collect`, and the component part of the hash.
- Each robot's table is rolled once on its death from a `RandomNumberGenerator` seeded with
  the run seed, a fixed salt and the robot's spawn number (`Sim.robot_serials`), so death
  order never changes a roll. Both numbers of each line are always drawn.
- `Sim.set_component_rules` before the first tick switches drops on. Without it nothing
  drops and the hash is untouched. With it, the rules, heaps, `collected` and every robot's
  `RobotDef.values_hash(true)` (drop table included) join the hash.
- New `SimEvent.Kind.COMPONENT_COLLECTED` (appended, so existing kind numbers stand) with a
  new `component` field naming the kind.
- `ComponentList.parse` skips `pickup.json`, which shares the components folder.
- `sim.gd` is 310 lines (was 293); the setter's checks live in `ComponentPickup.install`.
