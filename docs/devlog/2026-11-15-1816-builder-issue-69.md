# 2026-11-15 Builder, issue #69 (lane-a)

Scheduled Builder run in lane-a. No pull request was open, so there was nothing to fix. M1
has no `ready` lane-a issue left, so the run took the lowest-numbered one in M2: #69,
shields that recharge from energy and permanent hull damage (CMB-2, CMF-6, ARC-1, ARC-2,
ARC-4). The file is named in Israel time (UTC+2), like the entries before it.

## Summary

- `ShipState` gains `max_shield` and `shield` (shield points, 50), `shield_recharge`
  (shield points per second, 5) and `shield_energy_cost` (energy per shield point, 1). An
  empty shield refills in ten seconds for half the pool.
- `ShipState.apply_damage(amount)` is the one way damage reaches a ship: shield first, the
  rest to hull, neither below zero, negative amounts ignored. `take_wall_hit` uses it.
- Energy order within a tick: the afterburner drains (or the pool recharges) first, then
  the shield buys what it can from what is left. Boosting never fails because the shield
  took the energy. Hull never recharges.
- `state_hash()` appends `shield` when it differs from `max_shield`, after hull, the same
  pattern hull uses.
- `ShipTuning` and `default_ship.json` gain the three keys with ranges: `max_shield`
  0..10000, `shield_recharge` 0..1000, `shield_energy_cost` 0.1..100. `apply_to` fills the
  shield.
- Wall tests now measure damage as shield plus hull lost; the full-thrust test watches the
  peak, because the shield recharges between hits.
- `game/tests/test_shields.gd`: 15 tests.
