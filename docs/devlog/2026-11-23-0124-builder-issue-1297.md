## Issue

#1297: acceptance suites take steps from part files in a subfolder and checks register
from their own files, so the M6 lanes never share a suite file (DEV-1, DEV-6, ARC-4,
ARC-5; decision records 0003, 0005, 0012). Filed in M1, the earliest open milestone, so it
came before the M6 lane-a issues.

## Summary

- `AcceptanceSuiteParts` (new): a suite's `"include": ["m6/perf", ...]` names part files
  `<folder>/<name>.json` under the suites folder, each holding only `{"steps": [...]}`.
  Their steps follow the suite's own, in the listed order, under the suite's name. A
  suite with an include may list no steps of its own; one with neither is still rejected.
- Rejected with the file named, so the run stops before anything flies: a missing or
  unreadable part, a bad part file (unknown key, bad step), a part name that is not
  `<plain>/<plain>` (no `..`, no deeper folder, no extension), a part listed twice, and a
  step id used twice anywhere in the suite and its parts.
- `load_named` already listed only files of the suites folder, so parts in `suites/m6/`
  are never suites of their own under `all` or `nightly`; a test now pins it.
- `AcceptanceCheckFiles` (new): every `.gd` in `res://acceptance/checks/` with
  `static func judges() -> Dictionary[String, Callable]` adds checks. The step parser
  validates against `known_checks()` (the built-in list plus these), and
  `AcceptanceChecks.run` and `judged_checks` take them too. A script that cannot be read,
  is not a RefCounted, has no static `judges`, returns a bad table, or names a check that
  already exists fails every suite with the file named. Scripts are listed through
  `ResourceLoader.list_directory`, which sees exported scripts by their source name. The
  folder ships with a README only.
- An empty suite: the runner now creates the report before the end-of-suite test, so a
  suite with no steps still writes a report, with `"result": "skipped"` and
  `"message": "no steps"`. `AcceptanceReport.all_passed` skips such reports; a run still
  needs one passing suite, so `--acceptance=m6` alone exits 1 for now, like a suite whose
  every step was skipped.
- New `suites/m6.json` including six empty parts: `ship`, `perf` (lane-a), `sound`,
  `effects` (lane-b), `look`, `base` (lane-c).
