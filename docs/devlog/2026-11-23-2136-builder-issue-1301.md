## Summary

- `xr/dev_menu.json`: new `sections` (Comfort, Controls, Mine, Display, as the issue
  suggested), `back_text`, `max_rows_visible` (6) and `max_row_chars` (28). Entries in no
  section (Update, Close) stay on the top list after the section rows. `seed_text` is now
  `#{seed}` so the longest seed fits 28 characters ("Level: #999999999999999999").
- `DevMenuSections` (new) reads and checks the section list; `DevMenuSpec` takes the new
  keys. A file without `sections` (the built-in fallback, test specs) shows one list as
  before, scrolled.
- `DevMenuRows` (new): which list shows (top or a section), the highlight, and the scroll
  window that keeps the highlight on screen. A on a section row opens it on its first
  entry; its Back row returns to the top list on that section's row; closing and reopening
  start at the top list. Hidden rows (update, Return to base) pass the highlight on as before.
- `DevMenuModel` keeps the presses; `kind()` gives `section` / `back` on those rows, and
  `close()` resets the list. `DevMenu` draws `max_rows_visible` lines from the window;
  `DevMenu.row_text` words a row: "Label: value" normally, "> Label: < value note >" when
  highlighted.
- `DevMenuValue` splits `plain_text` (every row) from `note_text` (highlighted row only);
  `value_text` still gives both, so the wiring and its tests read the same words.
- No action, result string or wiring changed; `dev_menu_wiring.gd`, `main.gd` and the hub
  files are untouched.
