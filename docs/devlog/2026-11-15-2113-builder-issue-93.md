## What Godot 4.7.2 has

Godot 4.7.2-stable (official, ed1daf0bf) headless `ClassDB` lists three core classes, all
instantiable, in the `openxr` module; the Vendors plugin (#10) is not needed:

- `OpenXRRenderModelManager` (`Node3D`): properties `tracker` (Any, None set, Left Hand,
  Right Hand) and `make_local_to_pose` (String); signals `render_model_added` and
  `render_model_removed`, each passing an `OpenXRRenderModel`.
- `OpenXRRenderModel` (`Node3D`): property `render_model` (RID).
- `OpenXRRenderModelExtension` (`OpenXRExtensionWrapper`): `render_model_get_all`,
  `render_model_new_scene_instance` and the other low-level calls.

They need the OpenXR extensions `XR_EXT_render_model` and `XR_EXT_interaction_render_model`
(names found in the engine binary), requested only when the project setting
`xr/openxr/extensions/render_model` is on. It was off.

## Summary

- `game/project.godot`: `openxr/extensions/render_model=true`. The extension is optional;
  a runtime without it starts as before.
- `ControllerModel.build()` adds a `RuntimeModels` child, an `OpenXRRenderModelManager` for
  its hand, local to the parent controller's pose. A runtime model hides the generic shape
  (`GENERIC_PARTS`); when the last one is removed, the shape comes back. Labels stay in
  both cases. New `has_runtime_model()`, `generic_shape_visible()`, `runtime_models()`.
- `XRRig` passes each hand's `XRController3D.pose` (`default`) to its model.
- No model files are committed; a test fails if a `.glb`, `.gltf`, `.fbx`, `.obj`,
  `.blend` or `.dae` appears under `game/`.
- Tests: `test_runtime_controller_model.gd` (7).
