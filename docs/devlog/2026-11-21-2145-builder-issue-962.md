#962: upgrade tree as data: craftable upgrades by branch and tier, with prerequisites and
component costs (CRF-3, CRF-6, CRF-7, ARC-4, ARC-1).

## Summary

- `core/upgrade_def.gd`: parses one upgrade file (`id`, `name`, `branch`, `kind`, `tier`,
  `requires`, `cost`, `grants`); a missing, unknown or bad key is an error naming the key.
  Id-shaped values reuse `ComponentDef.check_id` (read only, lane-b's file is unchanged).
- `core/upgrade_tree.gd`: `UpgradeTree.parse(texts)` takes file texts by name (core never
  opens files), sorts by id, and rejects with the file name and key: duplicate id,
  unknown branch or kind, a `requires` naming no upgrade, a cycle (named as
  `a -> c -> b -> a`), a tier not above every upgrade it requires, a cost not a whole
  number above 0. `missing(id, crafted, banked)` returns `""` or one reason; it is pure.
- `data/upgrades/`: 12 placeholder upgrades, 2 to 4 per branch, a tier-1 to tier-2 link in
  every branch and one tier-3 shield. Tier 1 spends scrap alloy and cell salts, tier 2 adds
  circuit shards, tier 3 adds core glass (CRF-7). Weapon upgrades grant the existing
  `needle_gun`, `slug_thrower` and `arc_lance` files; other `grants` ids name parts and
  modules that later issues will define.
