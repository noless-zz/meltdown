## Summary

- New `game/core/exit_rule.gd` (`ExitRule`), called once at the end of `Sim.step`: once
  the reactor is destroyed, a ship whose centre ends a tick inside the exit sphere around
  its start position while `meltdown_ticks_left > 0` escapes (`SHIP_ESCAPED`, velocity set
  to zero); when the countdown is at 0 every ship still flying is lost (hull 0,
  `SHIP_LOST_IN_MELTDOWN`, reported once). Before the reactor dies the start does nothing.
- An escaped ship (`ShipState.escaped`) is skipped by `Sim.step` (no input, no movement,
  no firing, slotting or reset), by robot shots (`ProjectileHits._hit_ship`), by robot
  targeting (`Sim.nearest_live_ship`) and by salvage pickup.
- `Sim.outcome()` returns `ExitRule.Outcome`: `RUNNING`, `ESCAPED` (some ship escaped
  and none is left flying) or `LOST` (none escaped and none is left flying). It and the
  escape flags join `state_hash()` only inside the reactor section.
- Exit radius: level file top-level `exit_radius` (metres held as whole mm, like every
  other length in the level file), default `ExitRule.DEFAULT_RADIUS_M` = 4 m when missing.
  `LevelDef` hands it to the reactor, which writes it into the replay's reactor line as
  an optional key; reactor lines written before this read back with the default, so no
  replay format bump. `exit_radius` inside the level's `reactor` object is rejected so a
  level has one place to set it. G2 now states `"exit_radius": 4.0`.
