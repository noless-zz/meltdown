# 2026-11-15 Builder, issue #104 (lane-a)

Scheduled Builder run in lane-a. No open pull request closed a lane-a issue, so there was
nothing to fix. The run took the lowest-numbered `ready` lane-a issue in M1: playtest #104,
a one-step update of the headset from the `main-latest` release (DEV-8, ARC-6, PLT-1,
DEV-7). The file is named in Israel time (UTC+2), like the entries before it.

## Summary

- `tools/update_quest.sh`: checks `adb devices` first (no headset: a clear message, exit 1),
  downloads `meltdown-quest-debug.apk` and its `.sha256`, refuses to install on a mismatch,
  runs `adb -s <serial> install -r` on every headset in state `device`, then prints the
  commit and `Built:` line from the release body (read from the GitHub API; if that fails
  the update still goes ahead and says `unknown`). `--launch` starts the game with
  `monkey`; on `INSTALL_FAILED_UPDATE_INCOMPATIBLE` it explains and uninstalls and retries
  only with `--uninstall-first`. Works with macOS's bash 3.2 and `shasum`.
- `tools/update_quest.ps1`: the same for Windows PowerShell 5.1 (`Invoke-WebRequest`,
  `Get-FileHash`, `Invoke-RestMethod`), with `-Launch`, `-UninstallFirst` and a launch
  prompt when neither is given.
- `tools/test_update_quest.sh` with stub `curl` and `adb` under
  `tools/fixtures/update_quest/bin/` and a trimmed copy of the real `main-latest` release
  response: 12 checks.
- `docs/install-on-quest.md`: "One-step update" section with ADB over Wi-Fi; the stale
  "fresh throwaway debug key" sentence now says `main` builds use the stable key.
