## Summary

- `ShipInput.aim_q`: ship-space aim in thousandths, default the nose `(0, 0, -1000)`.
- New `game/data/aim/look_aim.json` (`cone_degrees` 35, `gimbal_degrees_per_second` 180),
  parsed by the new `core/look_aim.gd` (`LookAim`), errors naming the key.
  `LookAim.new()` holds the same values; a test keeps them equal to the file.
- `ShipState.gun_direction` turns each tick towards the aim, clamped to the cone, at most the
  gimbal rate (`LookAim.turn_gun`, called from `Sim.step` before firing). Primary shots leave
  along it. It joins the ship hash only off the nose, and reaching the target sets it exactly,
  so a ship that aims and comes back hashes like one that never aimed. `Sim.set_look_aim`
  before the first tick. Bots keep aiming with the nose.
- Replay format 17: a ship's tick group carries three more numbers only when the aim is off
  the nose, and an optional `aim {json}` header line (`ReplayAimLine`). `ReplayInputSource`
  hands the replay's values to the session.
- Network protocol 3: flag bit 4 plus 12 bytes of aim, only off the nose; a nose input is
  still 31 bytes.
- New m2 step `look_aim_shot` (`look_aim_shot.replay`, test tunnel without robots, aim 10
  degrees right, fire for a second), `final_hash` 1998918371.
- Size limits: `Sim.state_hash` moved to `core/sim_hash.gd`; `Replay.from_text`'s loop moved
  to `ReplayHeader.read_text`.
- The four m3 `expected_level_hash` values changed: the level hash is the hash of the replay
  header text, which now starts `meltdown-replay 17`. Every `expected_hash` is unchanged.
