## Issue

#1137: the game reads `data/aim/` at level start, so look-aim and aim assist are tuned in
data (CMB-7, CMB-8, ARC-4, ARC-1, MP-2).

## Summary

- New `game/aim_data.gd` (`AimData`, outside `core/`): reads `look_aim.json` and
  `aim_assist.json`, parses them with `LookAim.parse_json` and `AimAssist.parse_json`,
  and hands them to `Sim.set_look_aim` and `Sim.set_aim_assist` before the first tick.
- A missing, unreadable, empty or rejected file logs one `[meltdown aim] <path>: <error>`
  line and the session keeps the defaults.
- `LevelStart.tunnel_session` and `LevelStart.level_session` (the two builders every
  start goes through: launch, restart, dev menu switch, run level) call `AimData.apply`.
- The values are not written into the session's replay. A first version recorded
  `replay.look_aim`; the full local run showed that the aim header line moves pinned
  level hashes (`test_m4_run_step`, `test_m4_shaft_step`, `test_m4_components_bank_step`),
  so it was dropped. The shipped files hold the simulation's defaults, which a replay
  without the lines flies.
- Replays and acceptance steps still build their sessions through `ReplayInputSource` and
  `ReplayAimLine` and are untouched. No comfort setting is read or written.
