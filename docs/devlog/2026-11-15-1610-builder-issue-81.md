## Summary

- `ShipInput.reset_to_start: bool` (default false), a fourth constructor argument.
- `Sim` keeps `start_positions` and `start_orientations`: recorded when the ships are
  created and again just before the first tick, so a ship placed before flying is honoured.
  `set_start_pose(index, position, orientation)` sets a start explicitly and, before the
  first tick, also places the ship there. Start poses are run configuration like `bounds`,
  so they are not hashed.
- On a tick whose input has `reset_to_start`, `Sim.step` puts that ship at its start pose
  with zero velocity before `ShipState.step`, so the same tick's thrust and turn still apply.
  Hull, energy and the afterburner lock are kept; other ships are untouched.
- `Replay` format version 4: an eighth number per ship, reset (0 or 1). Versions 1 to 3
  still load with reset off; a v3 line with eight numbers, a v4 line with seven, and a
  reset value other than 0 or 1 are rejected. Existing replay files and their hashes are
  unchanged.
- `game/tests/test_reset_to_start.gd`: 12 tests.
