## Summary

- New `RunShip` (`game/run_ship.gd`), held by `RunWiring.ship`: at each run level it reads
  the ship file, the fitting (`FittingStore`), the upgrade tree (every file in
  `data/upgrades/`) and builds the ship with `RunStartShip.build` from the run's profile
  and crew roles. Notes are logged once each with `[meltdown run]`; a ship that is still
  rejected flies the ship file. Nothing stops the run.
- `LevelStart.run_tuning(path)` gives that tuning only when the run flies `path` now;
  `session_for` passes it to `level_session`, so `--level`, `--seed`, the tunnel and the
  dev menu keep the plain ship file. `choose` gives a `--run` launch the default
  `FittingStore`. The loadout handed to `comfort.set_loadout` is the fitted one.
- Replays (ARC-2): no new record was needed. The replay's `tuning` line carries every
  feel value and its `weapon` lines the resolved weapons; utility modules never touch
  the sim. Tested by reading a fitted run level's replay back and flying it to the same
  hash.
- Acceptance: run steps may name scratch `profile` and `fitting` files
  (`AcceptanceFittedStart`, documented in `AcceptanceSuite`). A run step without them
  flies the plain ship file (`RunShip.enabled` off), so the pinned m4 hashes do not move
  even when crew joins during `shaft_rewards`. New m4 step `fitted_start` pins the level
  hash of run 12345's level 1 with a fitted needle gun and lattice shield and two shield
  technicians (files in `game/acceptance/fittings/`).
