## Summary

- `game/meta/update_check.gd` (`UpdateCheck`, `RefCounted`, pure logic):
  - `evaluate(release_json, running)` returns `status` (`update_available`, `up_to_date`,
    `unknown`, `error`), `reason`, the release `commit` and `built_unix`, and the
    `apk_url` and `sha256_url` of `meltdown-quest-debug.apk` and its `.sha256`.
  - The release commit comes from the "commit <sha>" text that `tools/release_notes.sh`
    writes into the body; `target_commitish` is used only when the body names none and
    it is a full hash. The build time comes from the `Built: ... UTC` line.
  - Malformed JSON, no asset list, or a missing APK or checksum asset is `error` with a
    reason. A running commit of `unknown` (editor run) is `unknown`, never an update; so is
    a release that names no commit anywhere.
  - `parse_sha256(text)` and `matches_sha256(bytes, digest)` (via `HashingContext`).
- Fixture `game/tests/fixtures/main_latest_release.json`: the real
  `releases/tags/main-latest` response fetched during this run, trimmed to the fields used
  plus a few for context. In it `target_commitish` (be8ad52) differs from the commit the
  body names (e1b0a77), which is why the body wins; a test pins that.
- Tests: `test_update_check.gd` (12).
