## Issue

#1245: in solo play, opening the menu pauses the game (owner's decision; PLT-7, CMF-8,
RUN-2, MP-2, DEV-7).

## Summary

- `LocalSession` keeps its pause as a set of reasons: `PAUSE_FOCUS` and `PAUSE_MENU`.
  `paused` reads true while any reason holds. Setting `paused` sets the focus reason
  only, so the focus callbacks and existing callers behave as before. `set_paused`
  and `paused_by` are new. The one-tick limit on resuming is armed only when the last
  reason clears.
- New `DevMenuPause.hold(session, open)` sets or clears the menu reason. It also holds
  the co-op note: no co-op code, comment only.
- `DevMenuWiring.attach` takes a `session_of` callable. `read` calls `DevMenuPause.hold`
  every frame with `is_open()`, after the menu has opened, closed or been closed by the
  hub, the flight test or an end screen.
- `main.gd` (still 300 lines) passes `get.bind("session")`. `restart_level` now carries
  only the focus reason into the new session. The menu sets its own reason again on
  the next `read`, so a restart or level change unpauses when the menu closes.
- The view already held while `session.paused` (hit shake, camera pose, countdown,
  vignette, end screens), so the menu pause gets all of that for free. The menu still
  follows the head and takes presses: its input path does not read the session.
- Acceptance: the steps take `"pause_by": "focus" | "menu"`. New m1 step `menu_pause`
  runs `basic_flight` with the menu reason held for 120 frames at tick 300, the
  `held_while_paused` check, and basic_flight's hash. The runner cannot tap the menu
  open, because it feeds no controller values. So the step sets the reason through
  `DevMenuPause.hold`, the same call the menu makes.
