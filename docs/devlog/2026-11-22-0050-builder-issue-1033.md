## Summary

- New `data/hub/hub.json`: page order and titles (Crew Quarters, Parts Locker,
  Workbench, Fitting Bay) and the empty-crew and empty-store texts. All words original.
- New `meta/hub_config.gd` (`HubConfig`) reads and checks that file: each of the four
  page ids exactly once, in any order, non-empty titles and texts; every error names
  the key. Split from the model to keep one class per file.
- New `meta/hub_model.gd` (`HubModel`): `pages()`, `page_title()`, `crew()` (role name,
  benefit stat and amount), `store()` (banked kinds with name and tier, tier first),
  `craftable()` (`Crafting.available`), `locked()` (with the `missing()` reason),
  `crafted()`, `fit_slots()` (fitted upgrade or the ship file's part per slot);
  actions `craft`, `fit(slot, id)` and `launch()`. Refusals are the `Crafting.craft` /
  `Fitting.check` reasons unchanged; a refused fit leaves the fitting as it was.
- The model also takes `CrewRoles` and `ComponentList`, which the issue did not list:
  crew role names and component tiers live there.

## Open questions

- `launch()` returns `{}` when the fitting fails `Fitting.check` (for example a fitting
  file naming an upgrade that is no longer crafted); `launch_check()` gives the reason.
- `fit` refuses a slot name that is not a fitting slot ("cargo[0]", "primary[2]") with
  its own reason, since `Fitting.check` has no such case.
- The locked and crafted lists reuse `Crafting._before` for their order so the Craft page
  sorts all three lists the same way.
