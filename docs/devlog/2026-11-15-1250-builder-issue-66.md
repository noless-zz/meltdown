# 2026-11-15 Builder, issue #66 (lane-c)

Scheduled Builder run in lane-c. No open pull request closed a lane-c issue, so there was
nothing to fix. The run took the lowest-numbered `ready` lane-c issue in M1: #66, comfort
rate caps and the preset 1 pitch limit (CMF-1, CMF-3, CMF-6, ARC-3).

## Summary

- `game/xr/comfort_input_filter.gd`: smooth yaw and pitch are clamped to
  `yaw_rate_cap_deg_per_s` and `pitch_rate_cap_deg_per_s` (`NO_LIMIT` = no cap; snap axes
  are not capped).
- Pitch limit: `filter()` takes an optional read-only `orientation: Basis`. The turn is
  predicted on a throwaway `ShipState` that copies only the orientation, so the
  prediction uses the simulation's own rotation code and the real ship is never written.
  Pitch that would carry the nose past the limit is dropped (a snap is all or nothing and
  still counts as fired; a smooth rate is scaled to end the tick at the limit). Pitch back
  towards the horizon always passes, and pitch that loops the nose over the vertical is
  rejected even though its elevation would look smaller.
- New static helpers `nose_elevation()` and `cap_q()`.
- `game/tests/test_comfort_rate_limits.gd`: 6 tests (separate file to keep the existing
  test file under 300 lines).

## Test results

Godot 4.7.2-stable, run locally exactly as CI does: 159 tests, 0 failed. With the caps and
the limit disabled, 4 of the new tests fail.

## Open questions

- Callers of a pitch-limited preset must pass the ship's orientation; the default
  `Basis.IDENTITY` means "level". The wiring issue (lane-b, `main.gd`) must pass
  `ships[0].orientation`.
- In preset 1, alternating pitch and yaw snaps can bank the ship (yaw about a pitched
  local up axis), after which a yaw snap can change the nose elevation. Only pitch input
  is limited, as the issue asks; a yaw snap can therefore push the nose a little past
  60 degrees in that case. Auto-level (out of scope here) is the natural place to fix it.
