## Summary

The owner's start-up recording (comment of 22:00) shows the picture zooming in, in steps,
about a second after launch. The cause is the dynamic render scaler from #1417. On the Quest,
lowering `Viewport.scaling_3d_scale` magnifies the picture instead of only lowering its
resolution. The controller also counts every vsynced frame as long, so it drops straight to
its 0.7 floor. Following the owner's order, the pull request holds only the stopgap:

- `xr/render_scale.json` ships `"enabled": false`.
- `RenderScaler.tick`: while the table is off, a headset viewport is held at exactly 1.0,
  which also overrides a lowered scale, and render times are not measured.
- The m6 `render_scale` check guards the off state: the scripted slow and fast frames must
  leave the scale at 1.0. With scaling on, it judges as before. `m6/perf.json` is unchanged.
- Tests: the shipped table is now tested off, and an on table is still tested going down and
  back. New `test_render_scaler_off.gd`.
