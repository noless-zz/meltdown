## Summary

- `ExitRule.count_down(sim)`: counts the reactor down only while `outcome()` is `RUNNING`, as
  the previous tick left it. `Sim.step` calls it in one line in place of `reactor.count_down()`
  (`sim.gd` 305 to 304 lines). `meltdown_ticks_left` now holds the value from the tick the run
  was escaped or lost, so `SHIP_LOST_IN_MELTDOWN` can no longer follow an escape.
- Escaped ships were already skipped by the step loop. The new tests pin that they stay parked.
- `MeltdownDebris`'s comment notes that its own clock keeps going after the run is decided, so
  debris still falls where no ship is flying. That changes nothing in the simulation.
- Tests that had the ship sitting in the exit when the reactor died, and expected the clock to
  keep running, now record the exit 8 m (or 20 m) away first: `test_reactor.gd` (2 tests),
  `test_meltdown_debris.gd` (1), `test_main_meltdown.gd` (1).
- `test_meltdown_timer.gd`'s `PLAIN_PINNED_HASH` moved from 1701626778 to 594744929: that replay's
  ship escapes on the tick the reactor dies, with 300 ticks left, which now hold.
- The `m3` suite's four escape replays end on the escape, so their hashes did not move.
