## Summary

- `craft_tree` section in `data/hub/hub.json`, read by `meta/hub_tree_layout.gd`: rows
  of words above the tree, the floor they stop at, tier and column spacing, the window's
  width, node size, pick radius, edge width, and which attribute icon each effect shows.
- `meta/hub_craft_tree.gd` (`HubCraftTree`): the station's rows, one per upgrade, in a
  depth-first walk, branch by branch. Stick down from a node goes to the first thing it
  unlocks. The layout gives each leaf a column and places each parent over its children,
  with tiers as rows, deeper ones lower. States are built, can build now and locked.
  The drawing comes as data: nodes inside a window scrolled to the selected node, edges
  cut at the window's sides, the selected node's edges lit, and an icon per detail row.
  Pressing still goes through `HubModel.craft`.
- `meta/hub_craft_rows.gd`: one fact per line (#1353). There is one cost line per
  component with have/need and its component icon, one line per effect with an
  attribute icon (or the upgrade's own), and one line per unlock with that upgrade's
  icon. A locked row's reason is now its first missing thing only, because the cost
  lines show the rest. This also changes the flat panel's Workbench page.
  `tests/test_hub_few_words.gd`: `LIST_ROWS` is empty, so every row fits `max_row_chars`.
- `xr/hub_tree_view.gd` (`HubTreeView`) shows each state by shape:
  - built: a square frame of four bars
  - can build now: a round frame
  - locked: drawn smaller, with no frame
  - selected: a wider ring in the selected colour
  Edges are thin bars. The view names no meta class.
- `HubStations`: a station's view is either a tree or a ship. The aim picks a node on the
  tree the same way it picks a slot on the ship. `HubStationScreen.text_floor_m` keeps
  rows off the tree.
- `HubText`: the Workbench station shows 3 rows while it draws the tree. Station and page
  rows moved into `HubStationPages`, so `hub_text.gd` stays under 300 lines.
- Acceptance: a new `workbench_tree` step in `suites/m6/base.json`
  (`acceptance/checks/workbench_tree_check.gd`). It checks the tree, edges, states, the
  selection ring and the row icons, then takes a screenshot. It then builds the first
  weapon through the Workbench and checks that its node is redrawn as built.
