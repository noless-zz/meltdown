## Issue

#1041: crew benefits add up with a cap per stat, and the shield bonus applies to the
ship's data (CRW-1, CRW-3, RUN-7, ARC-1, ARC-4).

## Summary

- `data/crew/roles.json` gains a required top-level `caps` object (`shield_max` 25,
  `map_reveal` 1, `salvage_slots` 2, `meltdown_seconds` 20, the Planner's guesses).
- `CrewRoles` (core) reads `caps`: every stat in `STAT_MAX` needs a whole cap from 1
  up; a missing stat, an unknown key or a cap below 1 is an error naming the key. New
  `cap(stat)` and `caps()` (sorted).
- New `meta/crew_benefits.gd` (`CrewBenefits`, static only): `totals(profile, roles,
  problems)` sums each stat and clamps it to its cap, keys sorted; members with an
  unknown role are skipped and the `CrewRoster.check` reason is appended to the optional
  `problems` array, so the return value stays a plain stat-to-amount dictionary.
  `apply_to_ship(ship_data, totals)` returns a copy with `shield_max` added to
  `max_shield`, clamped to `ShipTuning.RANGES`.
- The roles fixtures in `test_crew_roles.gd` and `test_crew_roster.gd` gain `caps`.
