## Summary

- New `game/acceptance/acceptance_checks.gd` (`AcceptanceChecks`, one per step): the
  samplers (frame budget, comfort, eye image, flight test, preset changes), the wait for
  the headset (`waits_for_xr`), and `run`, which maps a check name to its judge through
  one dictionary. Replay checks still go to `AcceptanceStateChecks`; any other name is
  "unknown check".
- `acceptance_runner.gd`: 304 to 253 lines. It makes the step's `AcceptanceChecks`, feeds
  it frames and ticks and calls `_checks.run(...)` in one line. The order of every call
  is the one it had (frame-budget sampler first, then the eye image, the error count, the
  log line, screenshots, the preset, then the scene samplers). `errors`, `xr_begun`,
  `xr_waited`, `xr_available()` and the new `flown()` are public so the judges can read
  them.
- New `game/acceptance/acceptance_step_parser.gd` (`AcceptanceStepParser`): `STEP_KEYS`,
  `MAX_EXACT_INT`, every step field check, `unknown_key` and `is_whole`, moved unchanged.
  `acceptance_suite.gd`: 300 to 130 lines; it reads the file and the list of steps.
- Moved references: `AcceptancePresetChanges` calls `AcceptanceStepParser.is_whole`;
  `test_acceptance_runner.gd` reads the flight test through the runner's `_checks`.
