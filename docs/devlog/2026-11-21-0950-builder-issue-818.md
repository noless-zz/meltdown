## Summary

- New step fields `controls` (a file of raw controller values per segment) and
  `left_handed` (default false), read by `AcceptanceControlsScript`. `left_handed` without
  `controls` is refused: a replay's `ShipInput` never passes the mapping.
- `ControlsInputSource` (extends `ReplayInputSource`) maps each tick's values through the
  scene's own `mapping` with `ControllerSampler.map_values`, the call the game makes each
  frame. It sets the step's hand setting and turns pitch inversion off for the flight, and
  `finish()` restores both when the flight ends. The step's `replay` only names the level.
- Runner: two lines (choose the source, call `finish()`), plus `finish()` on the seed-level
  failure path. `ReplayInputSource.finish()` is a no-op.
- Data: `m1_controls.controls.json` (sticks, grips, both lift buttons, afterburner, fire) and
  `m1_controls_mirrored.controls.json`, the same with every control on the other hand.
- `m1.json`: `right_handed_flight` and `left_handed_flight`, both `final_hash` 1617769301
  and `no_script_errors`. Two steps rather than one, so each flight reports its own hash.
- Two existing tests re-fly every suite step's replay directly; they now skip steps with
  `controls`. The m1 runner test's frame limit rose from 20000 to 24000.
