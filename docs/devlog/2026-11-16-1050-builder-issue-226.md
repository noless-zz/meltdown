## Summary

- New `game/view/robot_view.gd` (`RobotView`, `Node3D`): `show_robots(previous, current,
  alpha)` draws one pooled `MeshInstance3D` per robot at the blended pose (position
  lerped, rotation slerped, scaled by `def.radius` times the look's `scale`). It only
  reads the robots.
- Robots are paired by index between the two snapshots. A pair is only blended when the
  type matches and the robot moved no further than two ticks of its top speed plus 10 cm;
  otherwise it is drawn where it is. That stops a robot sliding across the tunnel when an
  earlier one is destroyed and the array shifts (#205), since `RobotState` has no id.
- New `game/view/robot_look.json`: a `default` look and one look per robot id (shape
  `sphere` / `box` / `capsule` / `prism`, `scale` 0.1..4, `emission_color`). Errors name
  the field, e.g. `"robots.drone.shape" is "torus", must be one of ...`. A missing or
  rejected file falls back to a grey sphere and warns.
- One mesh and material per type, shared by all robots of that type. Materials are
  shaded and emissive, so the shape reads under lights and the colour reads in the dark.
- Not wired into `main.gd`; that is lane-b's #228.
