## Issue

#1096: the aim assist module bends shots towards a robot just off the aim (CMB-7, CMB-8,
CRF-5, CRF-4, ARC-1, ARC-2, ARC-4, MP-2).

## Summary

- `ShipLoadout.AIM_ASSIST_MODULE` ("aim_assist") joins `UTILITY_MODULE_KINDS`.
- New `game/core/aim_assist.gd` (`AimAssist`): `parse_json` checks `cone_degrees`
  (0..45) and `range_m` (1..1000), errors naming the key; `bend(origin, direction,
  robots)` returns the direction to the nearest live robot centre within the cone and
  range, ties to the lower index, or the direction unchanged. A new `AimAssist` holds the
  shipped values (6 degrees, 60 m), like `LookAim`.
- `cone_degrees` is measured from the aim line (a half-angle), unlike `LookAim`'s
  full-width cone, so "3 degrees off" sits inside a 6-degree setting as the issue's tests
  expect. The class comment says so.
- `Sim.aim_assist` and `Sim.set_aim_assist` (before the first tick only), not hashed, as
  for `look_aim`.
- `ProjectileHits.fire` bends the shot, after look-aim, only when the firing ship has the
  module fitted.
- New data: `data/aim/aim_assist.json`, `data/upgrades/aim_assist.json` (utility, tier 1,
  2 scrap alloy + 3 cell salts: tier 1 may only cost tier-1 components, per
  `test_upgrade_tree`), `data/ship_parts/aim_assist.json`.
