## Issue

#869 (M3, RUN-4, GEN-3, ARC-2): `OpeningGraph` agrees with `KnownRoute` when a cave-in
splits a box.

## Summary

- `OpeningGraph.splits_by(debris, index)`: the splits one solid box entry makes, as (box,
  entry, axis, place). It calls `BoxSplit.splits` for that entry alone and keeps only
  splits that separate two of the box's own points (opening centres, reactor, start), the
  filter `KnownRoute._cuts` uses. The rule itself is not copied.
- `OpeningGraph.connected(closed, splits = [])` walks box parts instead of boxes; an
  opening joins the part of each box that holds its centre. With no splits it takes the
  old walk over boxes, which is still the common case.
- `DebrisEscape._held` counts an entry that splits a box as one that can close the route,
  so the guard rule holds a slab that would close the last way out, and `_evaluate` runs
  the full `KnownRoute` timing when a box is split, not only when an opening is blocked.
- Speed: every generated door splits its doorway box (1,018 splits on 676 of seeds
  0..999), so `BoxSplit` ran about twice per level in each of three passes. A coarse reach
  test skips boxes an entry cannot span, and `BoxSplit`'s answers are remembered by box,
  entry and radius (capped at 4,096).
