## Summary

- New `game/xr/inertia_drift.gd` (`InertiaDrift`): turns the change of the ship's
  velocity between frames, read in the ship's own frame, into a translation of the view
  opposite to it, clamped to `max_offset_m`, settling back to zero at a steady speed so
  the largest offset is gone within `settle_s`. Translation only; presets without
  `inertia_drift` get the identity, a preset change drops the offset at once, a paused
  frame (delta 0) holds still.
- New `game/xr/inertia_drift.json`: `lag_m_per_m_per_s` 0.002, `settle_s` 0.5,
  `max_offset_m` 0.04. Checked like `hit_shake.json`; `max_offset_m` may not pass
  `OFFSET_CEILING_M` (0.1 m), which a test keeps inside `HeadRecentre.HEAD_REACH`.
- New `game/drift_wiring.gd` (`DriftWiring`): loads the file (a rejected file is printed
  and the drift stays off), keeps copies of the ship's velocity and orientation, and
  answers the frame's offset. `comfort_wiring.gd` was at 300 lines, so it only gains the
  `drift` field and joins `drift.advance(preset, delta)` to the shake in
  `advance_hit_shake`; two comments were shortened to stay at 300.
- `rig_views.gd`: `place_guarded` hands the drift a copy of the shown ship each frame.
  `main.gd` is unchanged: it already puts `comfort.shake_offset` on the ship's pose where
  it places the rig, and that offset now carries the drift too. Because the ship is seen
  where the rig is placed, the drift runs one frame behind the simulation.
