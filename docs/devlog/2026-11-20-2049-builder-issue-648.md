## Summary

- `game/meta/android_installer.gd` (new, `AndroidInstaller`): the Java calls the probe proved on
  the Quest 3 (FileProvider content URI, `ACTION_VIEW` install intent), moved out of
  `InstallerProbeJava`, plus `may_install()` (`PackageManager.canRequestPackageInstalls()`) and
  `ask_install_permission()` (`ACTION_MANAGE_UNKNOWN_APP_SOURCES` for this package).
- `game/meta/update_install_bridge.gd` (new): the base the fake and `AndroidInstaller` share.
- `game/meta/installer_probe_java.gd`: uses one `AndroidInstaller` for the URI, the intent and
  its Java helpers; its steps and log lines are unchanged.
- `game/meta/update_install.gd` (new, `UpdateInstall`): checks the permission; if missing, says
  "The headset will ask to allow installs from this app; then tap Menu" and opens the system
  screen. Otherwise saves the running commit to `user://meltdown_last_build.json`, builds the
  URI and starts the installer. A hand-off that does not start says "Installer did not start:
  <reason>. Tap Menu to retry", removes the saved commit and keeps the APK.
  `take_update_message()` reads and clears the saved commit and returns "Updated from <old> to
  <new>" only when both are known and differ, logged with `MELTDOWN_UPDATE`.
- `game/update_wiring.gd`: on Android, `attach()` adds an `UpdateInstall`; `update_verified`
  hands the APK over and the notice shows the outcome. A menu tap retries a hand-off that waits
  for the permission or failed; after the installer opened, a tap checks again. On start the
  notice shows the "Updated from" line once, before the start-up check.
