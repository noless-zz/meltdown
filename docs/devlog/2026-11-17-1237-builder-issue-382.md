## Summary

- `--seed=<n>` on the command line, or the `meltdown_seed` intent extra, now flies the level
  `MineGenerator` builds for that seed. `LevelSwitch.requested_path()` returns one source
  string, a level file path or `seed:<n>`, and `LevelSwitch.load_level` turns either into the
  `LevelDef`. `main.gd` keeps calling `use_level(LevelSwitch.requested_path())`; only that
  line's comment changed, and it stays at 298 lines.
- `--level` (argument or extra) wins over any seed. A seed that is not only digits (at most
  18) is printed and the tunnel stays; so does a bad `--level` name even when a seed is given,
  so a typo is never covered by another level.
- New `game/seed_level.gd` (`SeedLevel`) reads the module files (name order), `generator.json`
  (loop bridges), `reactor.json`, `validator.json` and the default ship, builds the level with
  10 modules exactly as `tests/seed_sweep.gd` does, takes the exit radius from
  `level_defaults.json` (on the level and its reactor), and runs `LevelValidator`. A broken data
  file or a failing level is printed with its messages and gives null, so the tunnel stays.
- Robots are not placed: the issue asks for the reactor plan only. `robots.json` exists (#378)
  and the sweep gains robots in #399.
