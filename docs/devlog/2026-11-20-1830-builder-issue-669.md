Scheduled Builder run in lane-b. No open pull request closes a lane-b issue, so this run took

## Issue

#669: the nightly device run cannot post its result, because `post_acceptance.ps1` sorted the
whole issue list as one item.

## Summary

- `tools/post_acceptance.ps1`: `Invoke-Api` now unrolls every GET answer into one pipeline item
  per issue or comment (`Write-Items`). `Invoke-RestMethod` and `ConvertFrom-Json` write a JSON
  array as a single object, which broke the gate sort, the gate comment lookup and the
  regression issue lookup alike.
- New `-DryRunFixture <file>`: a JSON object whose keys are GET paths and whose values are the
  canned answers. The dry run feeds them through the same unrolling, so it takes the same code
  paths as a real run. Without it a dry run still finds nothing, as before.
- `tools/fixtures/post_acceptance/with_regression.json` and `no_regression.json`: gates in
  milestones 4 and 2 (and one without a milestone), an earlier result comment on the right gate
  and on the wrong one, an open regression issue, a pull request carrying the marker and an
  unrelated `playtest` issue.
- `tools/post_acceptance_checks.sh` (new): the report checks, moved out of
  `test_device_acceptance.sh` so that file stays under 300 lines (285 now), plus four new ones
  (lowest-milestone gate only, existing regression issue reused, new regression issue when none
  is open, passing run stops after the gate comment). `test_device_acceptance.sh` builds a
  failing and a passing results folder and calls it. It is not named `test_*.sh` because CI runs
  those without arguments.

## Test results

- `tools/test_device_acceptance.sh` with PowerShell 7.4.6 on Linux: all checks pass, including
  the two existing report checks (criterion 4).
- Against the old `Invoke-Api` (fixture plumbing only, no unrolling) the four new checks fail,
  so they cover the bug.
- `shellcheck tools/*.sh` and `tools/check_device_workflow.sh` clean.
- Godot was not run locally: no `game/` file changed. CI runs the full suite.
