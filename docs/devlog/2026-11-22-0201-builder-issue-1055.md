## Issue

#1055: shield, hull and engine upgrades fit into their own slots and change the starting
ship (CRF-4, CRF-3, SLV-2, CRW-3, ARC-4, ARC-1).

## Summary

- `Fitting` gains `parts`, one slot each for `shield`, `hull` and `engine` (`PART_KEYS`),
  kept apart from `KEYS` so the weapon and utility slot code (and the lane-c hub, which
  walks `KEYS`) is unchanged. A part upgrade fits only its own slot; any other slot
  refuses it with a reason naming that slot. `NOT_FITTABLE_YET` is gone and the class
  comment says what fits where. New `part_ids()`; `is_empty()` counts parts.
- The JSON text gains a `parts` object; a text without it reads with empty part slots.
- `FittingStore.VERSION` is now 2 and still reads version 1. Reason: a version-1 build
  rejects the unknown `parts` key as unreadable but does not lock, so it would save over
  a newer file and lose the fitted parts. With version 2 an older build locks instead,
  which is what the store's class comment asks of a new slot kind. `valid_for` also
  trims stale part slots.
- `RunStartShip.build` reads each fitted part's file from `data/ship_parts/` (new
  optional `parts_dir` argument for tests) and applies them with `ShipPartDef.apply`
  before the crew's benefits. A missing or rejected part file is skipped with a note.
