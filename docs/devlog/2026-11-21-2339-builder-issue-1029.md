## Issue

#1029: a suspended run keeps its chosen shafts, so a resumed run flies the same levels
(RUN-8, RUN-1, ARC-2, NAM-1).

## Summary

- `RunSave` (meta) gains `chosen`, written under the new key `chosen`. `VERSION` goes to 2
  so a build from before this change reports a new save as "from a newer build" (left
  untouched) rather than as unreadable. A version-1 file loads with an empty `chosen`, a
  version-1 file that has the key is refused, and a non-string or empty entry is an error
  naming `chosen`.
- `RunState` (core) gains `resumed(plan, shafts, components, next_level, chosen)` and
  `chosen_so_far()`. A resume refuses, with a reason, a `next_level` outside the plan, a
  shaft not in the offer for its depth, choices without a shaft offer, and a choice count
  other than one per earlier level (choice into the resumed level still due) or one more.
- New `meta/run_resume.gd` (`RunResume`): `to_save(state, ship, loadout)` and
  `resume(save, plan, shafts, components)`. It is not on `RunState` because `core/` may
  not depend on `meta/`, and not on `RunSave` because an existing layer test keeps that
  class free of the run's state class.
