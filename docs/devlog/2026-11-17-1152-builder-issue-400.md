## Summary

- New `game/view/map_route.gd` (`MapRoute`, a `Node3D`): draws the route as thin square bars
  through its points, one mesh surface for the whole route, and a cross (four bars along a
  cube's diagonals, so it reads as an X from any side) at each blocked centre. Zero-length
  segments are dropped. It never reads the session.
- `MapHologram` (`game/xr/map_hologram.gd`) owns one `MapRoute` and gains
  `show_route(points_m, blocked_m)`, `clear_route()` and `route()`. The level-space points are
  kept and re-fitted on every `build`, exactly like the exit and reactor markers, so the route
  sits in the explored boxes' space and follows the map when it re-fits. The file is now 298
  lines.
- The look: four optional keys in the existing `game/xr/map_look.json`, parsed by `MapLook`:
  `route_color` (white), `route_width_m` (1.5 mm), `blocked_color` (red), `blocked_size_m`
  (12 mm). The issue named `game/view/map_look.json` "new or extended"; the map's look file
  already lives in `xr/` and is read by the hologram, so it was extended rather than split.
- Bars instead of a line primitive because a line primitive is one pixel wide whatever the
  look says, so `route_width_m` could not come from data otherwise.
