## Issue

#17 Guard the core and gen layer rules with a source scan test (ARC-1, ARC-3, MP-2).

## Summary

- New `game/tests/test_layer_rules.gd`. It reads every `.gd` file under `res://core` and
  `res://gen`, recursively, and reports `<file>:<line>:` for each line that:
  - extends anything but `RefCounted` or a class declared in `core/` or `gen/` (a quoted
    `extends "res://core/..."` or `"res://gen/..."` path is also allowed);
  - names an API from the constant `FORBIDDEN_APIS`, which holds exactly the thirteen
    names the issue lists;
  - calls `randf`, `randi`, `randf_range`, `randi_range` or `randfn` as a global, or
    `randomize`, `pick_random` or `shuffle` in any form.
- A name matches only where it starts an identifier. `Node` therefore also reports
  `Node3D` and `NodePath`, and `Input.` does not report `ShipInput.new()`, which
  `core/replay.gd` uses.
- Comments are skipped, both whole lines and the part of a line after a `#` that is not
  inside a string.
- The scan function takes the source text as a parameter. Five further tests feed it
  snippets: four base classes outside the layers and an inner class, every entry of
  `FORBIDDEN_APIS`, nine unseeded random calls, one clean script that must give no
  report, and the class name collection.
- The scan fails if it finds no script under `res://core`, so a renamed folder cannot
  make it pass empty.
- `test_core_scripts_do_not_extend_node` is removed from `game/tests/test_sim.gd`.

No file under `game/core/` or `game/gen/` changed.

## Open questions

- `rng.randomize()` on a `RandomNumberGenerator` is reported, although the issue only
  names globals and arrays. It seeds from the clock, so it is unseeded randomness; say so
  if that is stricter than wanted.
- `rng.shuffle()` or a core function of our own called `shuffle` or `pick_random` would
  also be reported, because the scan cannot tell an array from another object.
- String literals are scanned like code. An error message in `core/` that contains, for
  example, `Node` at the start of a word would be reported.
- A `#` inside a multi-line `"""` string is read as the start of a comment, because the
  scan works one line at a time.
- The list is the one from the issue. It does not hold `get_node`, `SceneTree`,
  `Camera3D` or the physics servers; `FileAccess` stays out of scope as the issue says.
- Still open: `*.gd.uid` files and `game/openxr_action_map.tres` appear after import and
  were left uncommitted here (#18).
