# 2026-11-15 Builder, issue #115 (lane-c)

Scheduled Builder run in lane-c. The only open pull request was #144 (lane-b), so there was
nothing in this lane to fix. The run took the lowest-numbered `ready` lane-c issue in M1:

in Israel time (UTC+2), like the entries before it.

## Summary

- `game/xr/cockpit_spec.gd` (`CockpitSpec`): parses a cockpit JSON file like `ShipTuning`.
  Keys and ranges: window half-angles horizontal and vertical (10..90 degrees), strut width
  (0.005..0.05 m), frame distance from the eye (0.32..0.95 m; raised from 0.3 after review), glass tint alpha (0..1).
  Missing, unknown, non-number and out-of-range keys are rejected with the key named.
  `window_solid_angle()` compares how open two cockpits are.
- `game/xr/cockpits/`: `anchored.json` (25 x 15 degrees), `guided.json` (50 x 30),
  `open.json` (75 x 55), `glass.json` (90 x 75). Guesses for G1.
- `ComfortPreset.cockpit_file` names each preset's file. The existing enum
  `ComfortPreset.CockpitFrame` is renamed `CockpitKind`: a global class `CockpitFrame` and
  an enum of the same name do not compile. Stored values are unchanged.
- `game/xr/cockpit_frame.gd` (`CockpitFrame`, `Node3D`): origin at the eye, -Z ahead. A
  shell over the forward half of the view at the frame distance: solid panels outside the
  window, tinted glass inside it (none at alpha 0), struts along the window edges (none on
  an edge at 90 degrees). Cell edges always fall on the window edges. Quads and boxes in
  three `MultiMeshInstance3D`s, unshaded, no shadows, no collision. `set_spec()` rebuilds.
  Not added to the rig or the main scene (out of scope).
- Tests: `test_cockpit_frame.gd` (12); `test_comfort_preset.gd` covers the new field.

## Test results

Godot 4.7.2-stable, run locally exactly as CI does: 369 tests, 0 failed;
`tools/check_clean_import.sh` clean. The one `SCRIPT ERROR` in the output
(`test_reset_hold.gd:221`) is also on `main`. Mutations checked: doubling the panel
distance fails both distance tests; putting the window cells into the solid part fails two.

## Open questions

- Headset: are the window sizes right per preset, and does the solid shell read as a
  cockpit or as a dark wall? Colours are flat grey placeholders.
- The shell covers only the forward half of the view; looking straight back shows the
  tunnel. Fine for now, worth a look at G1.
- Panels near straight up and straight down overlap more than elsewhere; harmless, but an
  `ArrayMesh` shell would be lighter if the instance count ever matters.
- Multimesh transforms cannot be read back under the headless renderer, so `CockpitFrame`
  keeps its own copy (`instance_transforms()`) for the tests.
