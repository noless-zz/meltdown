## Issue

#991: the generator takes a robot-count scale, so a riskier shaft can give a busier level
(RUN-1, GEN-1, GEN-2, GEN-3, ARC-2, ARC-4).

## Summary

- `gen/robot_plan.gd`: `scaled(robot_scale := 1.0, placements := 0)` returns a copy whose
  count range is `round(min * scale)` to `round(max * scale)`. The top is capped at
  `max_per_module` robots in every module but the start's, but the cap never takes it below
  `max_per_level`, and the bottom never rises above the top, so a scale of 1.0 or more never
  gives a range below the file's. A scale outside 0..10 (or not finite) is an error on the
  copy naming `robot_scale`. The rule is in the class doc comment; `count_range` computes it.
- `seed_level.gd`: `level_of(generator, robot_scale := 1.0)` and `load_level(..., robot_scale
  := 1.0)` pass the scale through; at 1.0 the shipped plan is used untouched. `level_switch.gd`
  and the seed sweep are unchanged and keep 1.0.
- `gen/generated_level.gd` was not touched: the cap is applied to the plan copy, where the
  level's module count is known through `SeedLevel`.
