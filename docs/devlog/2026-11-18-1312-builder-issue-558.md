## Summary

Stopped with `needs-human` and no code change. The first acceptance criterion asks the game
to have the runtime end the session before quitting. That means calling
`xrRequestExitSession`, and Godot 4.7.2 does not let a script make that call:

- `ClassDB` (4.7.2-stable, headless) shows no exit, end or stop method on `OpenXRInterface`
  or `OpenXRAPIExtension`.
- `modules/openxr/openxr_api.cpp` never calls `xrRequestExitSession`, at `4.7.2-stable` or on
  `master`. Quitting, or `XRInterface.uninitialize()`, reaches `destroy_session()`, which
  calls `xrEndSession` on a running session. That call is where
  `XR_ERROR_SESSION_NOT_STOPPING` comes from.
- `get_instance_proc_addr` returns only a pointer, and GDScript cannot call it.

A probe that waits for `session_stopping` would therefore always time out. It would add about
2 s to the smoke run and change nothing in the log, so it was not built. The issue comment
lists four options: a GDExtension, an upstream Godot request, the reporting part alone, or
won't-do.
