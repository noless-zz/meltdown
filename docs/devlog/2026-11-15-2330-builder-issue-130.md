## Summary

- No Android plugin and no Gradle change. The Godot 4.7.2 Android template already declares
  `androidx.core.content.FileProvider` with the authority `<package>.fileprovider`, serving the
  app's files directory (`files-path` at `/`, see `platform/android/java/lib` in the engine
  source). So the cheapest approach in the issue works on paper: `JavaClassWrapper` builds the
  content URI and an `ACTION_VIEW` intent with the APK MIME type. `ci.yml` and
  `docs/licences.md` are untouched.
- `game/meta/installer_probe.gd` (`InstallerProbe`): copies `getPackageCodePath()` to
  `getFilesDir()/meltdown_installer_probe.apk`, hands it to the installer and returns
  `started`, `unsupported: <reason>` or `error: <reason>`; logs
  `MELTDOWN_INSTALLER_PROBE <status>`. Java exceptions are read back with
  `JavaClassWrapper.get_exception()` and reported as `error`.
- How it is asked for: `-- --installer-probe` on desktop, or the intent extra
  `meltdown_installer_probe` on the headset. Godot strips `command_line_params` from intents
  sent to exported activities and the launcher alias is exported, so a custom extra is the
  only way to pass a flag with `adb shell am start`. Never in a non-debug build.
- `game/export_presets.cfg`: the Quest preset adds `REQUEST_INSTALL_PACKAGES` through
  `permissions/custom_permissions`, because 4.7.2's built-in permission list has no entry for it.
- `game/main.gd`: one line at the end of `_ready` calls `InstallerProbe.run_if_requested()`.
