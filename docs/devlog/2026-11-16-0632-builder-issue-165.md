## Summary

- `game/acceptance/acceptance_runner.gd` (`AcceptanceRunner`, a `Node`): started by
  `-- --acceptance=<suite>` or the intent extra `meltdown_acceptance=<suite>`. Per step it
  sets the comfort preset, swaps in a `LocalSession` built from the replay's seed, walls
  and tuning, and drives the scene's own `advance_frame` one tick per frame with the
  replay's inputs (main's `_process` is paused meanwhile, so the controllers fly nothing).
  Then it runs `final_hash`, `xr_session` and `no_script_errors`, records the step,
  writes `user://acceptance/<suite>-<short commit>.json`, prints the marked log lines and
  quits 0 or 1. A missing or rejected suite quits 1 with its message before anything flies.
- `xr_session` without a runtime is `skipped`; with `"required": true` it fails. The new
  `required` key is parsed and validated in `AcceptanceSuite`/`AcceptanceStep`.
- Two small helpers in `acceptance/`: `ReplayInputSource` (inputs indexed by tick, counts
  overruns) and `AcceptanceErrorLog` (a `Logger` counting script errors; the test runner's
  logger lives in `tests/`, which exports leave out).
- `InstallerProbe.android_runtime()` and `intent_extra(runtime, name)` are now public, so
  both switches read the intent the same way. `main.gd` gains one call.
