## Summary

- `Fitting.check` already refused one id in two slots; nothing in the hub stopped
  offering it, so the owner saw "Mount" for a second slot. New `meta/fitting_slots.gd`
  (`FittingSlots`) names slots, finds where an upgrade is (`slot_of`), puts one in a
  slot, moves it in one step (`move`) and repairs a doubled fitting
  (`without_doubles`). `Fitting.slot_of` and `Fitting.move` call it.
- `FittingStore.load_fitting` loads a file that names an upgrade twice with the later
  slot emptied, logs one line and sets `message`; it never fails on it.
- `HubModel.move(slot, id)` moves through `Fitting.check`, as `fit` does. `fit` now uses
  `FittingSlots.put`; `_parse_slot` and `_copy` moved to `FittingSlots`.
- Fitting Bay: an upgrade fitted nowhere is offered as "Mount <name>"; one fitted in
  another slot as "Move <name> here (now in Primary 1)", action `move`. `HubWiring`
  saves the fitting after a move as after a fit.
- Crew Quarters: one row per role, "Cargo Rigger ×3: +2 salvage slots (max)". The total
  is what the run gets: the summed amount clamped to the stat's cap, as
  `CrewBenefits.totals` does. "(max)" marks a capped total (new `crew_capped_row`).
  New `meta/crew_groups.gd`.
- Parts Locker: under each component, "For <three upgrade names> and 15 more"
  (Scrap Alloy is in 18 upgrade costs) or "Not used yet". New `meta/component_uses.gd`; at most three names, then
  a count, so a line stays short.
- Acceptance: new step `fit_move` in `suites/m6/base.json` with lane-c's new check file
  `acceptance/checks/fit_move_check.gd`. It flies m4's craft-and-fit flight, builds the
  first weapon, mounts it in Primary 1, checks Primary 2 offers no second mount, moves
